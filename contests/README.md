# 대회 기록

대회 기록은 실제로 참가했거나 virtual을 수행한 회차만 `contests/<slug>.md`에 남긴다. 대회와 virtual은 주제 학습을 시작하기 위한 선행 조건이 아니라 주기적인 점검 선택지다. 시기와 분량은 [로드맵](../ROADMAP.md)에 따른다.

## 최소 형식

대회 노트의 YAML 메타데이터에는 다음 필드를 둔다.

```yaml
---
title: "대회 제목"
updated: "YYYY-MM-DD"
tags:
  - "codeforces"
url: "https://codeforces.com/contest/..."
---
```

`url`은 해당 대회의 실제 원문 URL이다. 판정, 도움 여부, 재풀이 여부 같은 상태는 확인한 뒤 본문에 적고, 확인하지 않은 값은 `unknown`으로 남긴다. rating을 다른 체계로 환산하거나 자동 진도 데이터베이스를 만들지 않는다.

## 회차와 결과 구분

[대회 템플릿](template.md)과 [대회 복기 스킬](../.agents/skills/review-algorithm-contest/SKILL.md)을 사용한다. 목표 경계·올솔 판정 조건·참가 빈도·시간 예산은 [로드맵](../ROADMAP.md#목표와-측정)에서 관리한다.

실전 올솔, 미견 virtual 올솔, 종료 후 업솔빙 전체 AC, 기출 재풀이 올솔은 다른 결과다. 전체 문제 수·공식 제한 시간·실제 측정 시간·노출·도움·판정 출처를 확인하고 해당 조건의 전 문제 AC가 있을 때만 올솔로 남긴다. 시간 내 `5/7`과 이후 업솔빙 `7/7`은 같은 회차 안에서 구분한다. 도움 받은 virtual은 일반 연습이며, 노출·도움 미확인을 독립 측정 성공으로 쓰지 않는다.

rating을 남기면 공식 출처·확인일을 붙이고 최초 도달일과 현재 rating을 구분한다. 단일 performance나 한 대회의 올솔로 rating 도달을 대신하지 않는다. 조사한 ABC의 시간·문제 수를 다른 회차에 자동 적용하지 않는다.

## 기록 순서

실제 종료한 회차의 형식·참가일·공식 시간·측정 구간·전체 문제 수·사전 노출·도움을 본문에 적는다. 문서 작성일인 `updated`를 참가일로 대신하지 않는다. 진행 중 실전·측정용 virtual의 풀이·디버깅 요청은 종료 후 복기로 돌린다. 같은 회차는 기존 문서에 병합하고 다른 날짜의 실제 virtual 재참가만 별도 회차로 구분한다.

제한 시간 내 직접 시도한 문제와 확인한 판정, 종료 후 선택한 업솔빙의 막힌 원인·해설/힌트 시점·직접 구현·실행자를 따로 남긴다. 시간은 관찰/사용자 보고·근사·미측정으로 구분하며 누적 제출 시각을 순수 사고 시간으로 만들지 않는다. 공식 직접 확인·사용자 보고·비공식 제출 자료도 구분한다. 고정된 추가 업솔빙 분량을 요구하지 않고 로드맵의 같은 주간 예산 안에서 선택한다.

완료된 대회의 설명을 복사하지 않는다. 필요한 경우 자기 풀이와 배운 점을 적고, 문제 원문은 각 문제의 URL로 연결한다. 문제를 별도 노트로 남길 때는 [문제 노트 템플릿](../templates/problem-note.md)을 기존 `atcoder/`, `codeforces/`, `cses/` 또는 `leetcode/` 코드 옆에 동일한 basename으로 복사하고, 실제 `.py` 파일을 노트 기준 상대 경로로 연결한다.

`contests/template.md`는 복사해 쓰는 참고 템플릿이며 자동 기록이나 자동 검사 대상이 아니다.
