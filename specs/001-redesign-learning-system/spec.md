# 기능 명세: 주제와 난도에 따른 알고리즘 학습 체계 개편

**작업 브랜치**: `main` — 브랜치 생성 훅이 없어 현재 브랜치를 유지한다.

**작성일**: 2026-10-19 KST

**상태**: 로컬 반영 완료 — 2026-10-19 KST 사용자의 “승인 및 진행”으로 명세를, “승인할게. 진행해”로 계획을 승인받았다. 공식 Run `1d02e086`은 여섯 단계 모두 `completed`이며 T001–T035를 마쳤다. 승인된 운영 문서 8개를 반영했고 기존 단위 검사 실패 1개·사용자 4주 시범 미시작·원격 미반영을 검증 가이드에서 구분한다. 본문의 단계 제한은 각 검토 승인 전의 경계이며 실제 학습 운영 기준은 ROADMAP이다.

**입력**: 사용자의 원 요청 전체와 추가 확정 조건, 2026-10-19 조사 결과, 제안 및 실행 경계를 반영한다. 주제를 선택하여 난도를 올리고 직접 설계·구현·검증하면서 성장하는 기존 학습 저장소의 운영 개편이다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 실제 현재 위치에서 다음 학습 시작 (우선순위: P1)

학습자는 최신 대회 근거와 현재 코드를 바탕으로 다음 과제 하나를 받는다. 이미 수행한 SCC 구현을 처음부터 다시 배우거나, 미구현 DAG DP를 완료한 것으로 취급하지 않는다.

**우선하는 이유**: 출발점이 틀리면 제한된 시간을 이미 아는 내용에 쓰거나 필요한 연결을 건너뛴다.

**독립 검증**: 현재 코드와 오래된 재개 문장만 제공해도, 대회나 다른 주제의 학습 없이 올바른 다음 행동과 미확인 범위를 제시할 수 있다.

**인수 시나리오**:

1. **주어진 상태**: SCC·축약 그래프가 있고 동전 수를 구하는 DP는 비어 있다. **행동**: 학습을 재개한다. **기대 결과**: 기존 구현에서 이어서 SCC별 값 집계와 DAG DP의 설계·직접 구현을 과제로 삼고, SCC 입문 시험을 반복하지 않는다. (FR-001, FR-002)
2. **주어진 상태**: 오래된 기록은 rating 972·ABC478, 전달된 최신 조사 결과는 1065·ABC480이다. **행동**: 출발점을 설명한다. **기대 결과**: 조사일·출처·재확인 한계와 함께 후자를 사용하고, performance 1532를 개별 기법 숙달로 바꾸지 않는다. (FR-001, FR-003)
3. **주어진 상태**: F/G를 읽거나 시도했는지와 도움 여부를 모른다. **행동**: 다음 점검을 고른다. **기대 결과**: 원인을 단정하지 않고 새 문제의 접근 선택·정당성·구현·시간 배분을 관찰한다. 과거 이력 답변을 학습 시작의 필수 조건으로 삼지 않는다. (FR-003, FR-004)

### 사용자 이야기 2 — 주제를 선택하고 적정 난도로 확장 (우선순위: P1)

학습자는 DP, SCC, 이분탐색 등 원하는 주제를 고르고, 필요한 선수 지식을 연결하면서 기초·응용·심화로 진행한다. 여러 주제를 다룬 뒤 다시 방문할 수 있다.

**우선하는 이유**: 넓은 범위를 다루려는 목표와 난도 상승을 함께 지원해야 한다.

**독립 검증**: 주제 지도와 진입·이동 기준만으로 임의의 주제에 대한 현재 진입점, 다음 난도, 재방문 조건을 선택할 수 있다.

**인수 시나리오**:

1. **주어진 상태**: DP 다음에 SCC, 이후 이분탐색을 원한다. **행동**: 주제 순서를 정한다. **기대 결과**: 해당 과제에 필요한 선수만 확인하고 선택을 지원한다. 한 주제의 최고 난도 완주를 이동 조건으로 요구하지 않는다. (FR-005, FR-006)
2. **주어진 상태**: 서로 다른 대표 변형 두 개를 추가 핵심 힌트 없이 설계·구현·검증하고 적용 조건과 복잡도를 설명했다. **행동**: 다음 과제를 고른다. **기대 결과**: 응용 난도를 잠정 상향하거나 다른 주제로 이동하고 재방문 조건을 남긴다. 다른 날 독립 재현 없이 장기 숙달로 기록하지 않는다. (FR-007, FR-009)
3. **주어진 상태**: 문제 해결에 필요한 핵심 단계 여러 개가 낯설거나 같은 공백이 반복된다. **행동**: 난도를 조정한다. **기대 결과**: 해당 선수 또는 단순한 변형으로 보완하고, 고정 시간이 지났다는 이유만으로 정답을 공개하지 않는다. (FR-008, FR-012)
4. **주어진 상태**: 서로 다른 자료의 문제 문자나 별 개수가 같다. **행동**: 문제를 비교한다. **기대 결과**: 같은 절대 난도나 rating으로 환산하지 않고 실제 선수·풀이·도움에 따라 배치한다. (FR-006, FR-018)

### 사용자 이야기 3 — 충분히 혼자 부딪히고 필요한 도움 받기 (우선순위: P1)

학습자는 새 기법의 필요한 원리를 배운 뒤 직접 설계하고 백지에서 구현·실행한다. 익숙한 주제나 혼합 문제에서는 독립 시도부터 시작하며, 막힌 부분에 맞는 도움을 받는다.

**우선하는 이유**: 이 개편의 중심 결과는 자료 소비나 정답 코드 수집보다 학습자 자신의 문제 해결 경험이다.

**독립 검증**: 신규 기법, 익숙한 주제, 혼합 문제, 힌트 요청의 네 상황에서 수업 흐름과 도움 경계를 각각 검토할 수 있다.

**인수 시나리오**:

1. **주어진 상태**: 처음 배우는 기법이다. **행동**: 회차를 시작한다. **기대 결과**: 목적·핵심 생각·작은 예제·적용 조건을 설명한 뒤 학습자가 설계·구현·실행·반례 검토를 맡는다. (FR-010)
2. **주어진 상태**: 접근 선택을 점검하는 혼합 문제다. **행동**: 독립 시도한다. **기대 결과**: 사전에 태그·사용 알고리즘·해법을 노출하지 않고, 제출된 코드·설명·출력에서 피드백한다. (FR-011)
3. **주어진 상태**: 새 아이디어를 계속 탐색하거나 특정 경계에서만 막혔다. **행동**: 진행하거나 힌트를 요청한다. **기대 결과**: 독립 작업을 이어가거나 그 경계에 필요한 최소 도움을 제공하고 전체 과제로 돌아간다. 연속 한 줄 퀴즈를 기본 흐름으로 삼지 않는다. (FR-012)
4. **주어진 상태**: 완성 코드 제공이나 사용자 파일 수정을 요청하지 않았다. **행동**: 리뷰한다. **기대 결과**: 사용자 풀이를 교체하지 않는다. 정답을 명시적으로 요청하면 설명·코드를 제공할 수 있으며 도움 범위를 구분한다. (FR-013, FR-020)

### 사용자 이야기 4 — 주 5–7시간 안에서 지속하고 재조정 (우선순위: P1)

학습자는 기본 주, 대회 주, 시간이 줄어든 주에도 총량을 관리한다. 처음 4주는 운영을 시험하고 결과에 따라 과제 수와 난도를 조정한다.

**우선하는 이유**: 기존 주 9–13시간 운영은 확정된 시간 제약을 충족하지 못한다.

**독립 검증**: 5시간·6시간·7시간 예시와 100분 ABC가 있는 주의 합계를 계산하고, 4주 계획의 이월 상황을 적용해 본다.

**인수 시나리오**:

1. **주어진 상태**: 주간 가용 시간이 5시간이다. **행동**: 기본 주 또는 대회 주를 선택한다. **기대 결과**: 복기·기록까지 포함한 합계가 300분이고, 9–13시간 분량이나 추가 숙제를 남기지 않는다. (FR-014, FR-015)
2. **주어진 상태**: 대회에 참가한다. **행동**: 주간 계획을 바꾼다. **기대 결과**: 기존 활동을 대회·복기로 대체하며, 매주 참가나 대회 두 개의 중복을 의무화하지 않는다. (FR-015)
3. **주어진 상태**: 첫 주의 과제가 다음 주까지 이어지거나 한 주를 쉬었다. **행동**: 다음 주를 계획한다. **기대 결과**: 미완료를 그대로 유지하고 뒤의 신규 범위를 줄인다. 밀린 분량을 몰아넣지 않는다. (FR-016)
4. **주어진 상태**: 시범 4주가 끝났다. **행동**: 운영을 검토한다. **기대 결과**: 실제 시간·독립 작업·도움·반복 오류·지연 재현을 근거로 유지·축소·상향을 정한다. rating 상승이나 올솔을 필수 성과로 삼지 않는다. (FR-016)

### 사용자 이야기 5 — 명세를 검토한 뒤 단계별로 개편 (우선순위: P1)

학습자는 학습 방향과 기본값을 검토한 뒤 계획 진행 여부를 결정하고, 계획도 별도로 검토한다.

**우선하는 이유**: 명세 작성 요청은 실제 학습 운영이나 사용자 풀이의 즉시 변경 승인이 아니다.

**독립 검증**: 생성물과 변경 목록을 읽어 현재 작업이 명세·품질 검토에 한정되고, 다음 단계가 명시 승인 전 실행되지 않는지 확인한다.

**인수 시나리오**:

1. **주어진 상태**: 명세 품질 검사가 통과했다. **행동**: 완료 보고한다. **기대 결과**: 검토할 기본값을 제시하고 `review-spec` 승인을 기다린다. 계획 단계나 ROADMAP·STATE·스킬 개편을 먼저 수행하지 않는다. (FR-024)
2. **주어진 상태**: 헌법 문서가 빈 템플릿이다. **행동**: 지침 근거를 판단한다. **기대 결과**: 확정·비준된 헌법으로 주장하지 않고 실제 저장소 지침과 학습 스킬을 따르며, 후속 계획에서 상태를 명시한다. (FR-025)
3. **주어진 상태**: 문서 개편 요청만 있다. **행동**: 범위를 정한다. **기대 결과**: 새 웹 앱·대시보드·DB·자동 수집기와 커밋·push·제출·배포를 추가하지 않고 기존 사용자 파일을 보존한다. (FR-023, FR-026)

### 사용자 이야기 6 — rating과 ABC 올솔을 따로 점검 (우선순위: P2)

학습자는 AtCoder 파랑 → 노랑, ABC 실전 올솔, 장기 Codeforces 빨강을 서로 다른 목표로 확인한다.

**우선하는 이유**: rating과 특정 대회의 전 문제 해결은 평가하는 사실이 다르다.

**독립 검증**: 실전, 미견 virtual, 종료 후 업솔빙, 기출 재풀이 네 결과를 각 지표에 분류하고 rating 도달과 혼동하지 않는지 확인한다.

**인수 시나리오**:

1. **주어진 상태**: ABC 종료 후 F/G까지 AC를 받았다. **행동**: 성과를 기록한다. **기대 결과**: 업솔빙 전체 AC로 기록하고 100분 실전 올솔이나 rating 목표 달성으로 기록하지 않는다. (FR-017, FR-018)
2. **주어진 상태**: 처음 보는 과거 ABC를 100분 측정용 virtual로 진행한다. **행동**: 진행 중 도움을 요청한다. **기대 결과**: AI 풀이·디버깅은 종료 후 복기로 돌린다. 도중 도움을 사용하면 독립 측정 결과에서 제외하고 연습으로 구분한다. (FR-019)
3. **주어진 상태**: 이미 본 대회를 다시 100분 안에 모두 풀었다. **행동**: 기록한다. **기대 결과**: 기출 재풀이 올솔로 분류하고 미견 virtual·실전 성과와 합산하지 않는다. (FR-017)
4. **주어진 상태**: 노랑 목표 부근에서 rating 점검 대회를 고른다. **행동**: 참가 범위를 확인한다. **기대 결과**: 해당 회차의 최신 rated 범위와 ARC 형식을 확인하고 ABC 올솔 연습을 별도로 유지한다. Codeforces 기준선은 별도이며 플랫폼 간 환산하지 않는다. (FR-018)

### 사용자 이야기 7 — 확인한 경험만 기록하고 짧게 재개 (우선순위: P2)

학습자는 실제 코드·출력·도움·온라인 판정 출처·다른 날 재현을 구분해 요청한 범위에 저장하고, 다음 세션에 남은 한 행동부터 이어간다.

**우선하는 이유**: 파일 존재나 에이전트 검증을 학습자의 독립 해결로 오인하면 다음 과제도 잘못 배치된다.

**독립 검증**: 샘플 통과, 사용자 보고 AC, 비공식 제출 자료, 같은 날 도움 없는 재구현, 다른 날 독립 재현의 예시를 각각 분류한다.

**인수 시나리오**:

1. **주어진 상태**: 코드만 있고 실행·도움·판정은 모른다. **행동**: 학습 기록을 작성한다. **기대 결과**: 구현 존재만 확인하고 나머지는 미확인으로 남긴다. (FR-020)
2. **주어진 상태**: 설명·힌트 또는 `이해했어`만 받았다. **행동**: 대화를 마친다. **기대 결과**: 노트·진도·사용자 코드를 자동 갱신하지 않는다. 명시적인 저장 요청이 있을 때만 해당 범위를 기록한다. (FR-021)
3. **주어진 상태**: 개편을 후속 구현한다. **행동**: 문서 책임을 정한다. **기대 결과**: 범위·운영, 짧은 재개 위치, 자료 출처, 학습·기록 절차의 기준 위치를 분리하고 같은 진도 이력을 여러 곳에 복제하지 않는다. 기존 기록과 연결이 보존된다. (FR-022, FR-023)

### 경계 상황

- 최신 계정 자료에 접근할 수 없으면 마지막 확인일과 출처를 유지하고 재조회 실패를 표시한다. 검색 캐시나 오래된 STATE로 최신 값을 덮지 않는다. (FR-001)
- F/G 제출 부재, 한 번의 높은 performance 또는 느린 누적 AC 시각만으로 미시도·지식 부족·구현 지연·도움 없는 해결을 단정하지 않는다. (FR-003)
- 과거에 본 문제이거나 풀이를 기억하면 접근 선택의 독립 측정에서 제외하고 다른 미견 문제를 고른다. (FR-004, FR-011)
- 필요한 선수 지식이 비어 있으면 그 부분만 보완한다. FFT를 시작하기 위해 유량 등 무관한 갈래의 완주를 요구하지 않는다. (FR-005)
- 4주 동안 특정 주제를 끝내지 못해도 실패·완료로 꾸미지 않고 독립 시도와 막힌 위치를 근거로 범위를 조정한다. (FR-016)
- 5시간도 확보하지 못한 예외 주는 실제 시간을 남기고 핵심 과제 하나 또는 휴식을 선택한다. 5시간을 했다고 기록하거나 다음 주에 빚으로 넘기지 않는다. (FR-014)
- 대회 시간이 100분과 다르면 해당 공식 시간을 사용하고 다른 활동을 줄인다. 이미 시작한 대회·측정용 virtual에서 AI 도움을 받아 독립 성과로 유지하지 않는다. (FR-015, FR-019)
- 단순 입출력 준비만 요청하면 알고리즘 본문을 대신 채우지 않는다. 명시적으로 받은 코드도 독립 작성으로 기록하지 않는다. (FR-013, FR-020)

## 요구사항

### 기능 요구사항

#### 출발점과 주제 운영

- **FR-001**: 출발점에는 기준일·계정·최신 대회·rating·rated 참가 수·최근 performance와 출처·확인 한계를 제시해야 한다. 오래된 기록과 현재 코드가 다르면 차이를 드러내고 더 최신의 확인 근거를 우선해야 한다.
- **FR-002**: 현재 재개점은 확인된 SCC·축약 그래프와 미구현 DAG DP의 연결이어야 한다. 재개 관문으로 기존 SCC의 기초 강의·재구현을 반복하게 하거나 Coin Collector를 완료·AC로 기록해서는 안 된다. 이후 다른 날의 재현 점검은 해당 목적에 맞게 선택할 수 있다.
- **FR-003**: rating, 한 대회의 performance, 문제별 누적 AC 시각, 주제별 학습 증거를 구분해야 한다. 미확인 도움·F/G 열람·시도 여부 및 약점 원인을 추정 사실로 기록해서는 안 된다.
- **FR-004**: 현재 확인된 A–E 경험을 출발점으로 삼고, F/G 및 새로운 문제에서 접근 선택·정당성·구현·시간 배분을 점검해야 한다. 처음부터 A–E 기초 전부를 재시험하거나 F/G 문자만으로 과제를 고정해서는 안 된다.
- **FR-005**: 사용자가 주제를 지정할 수 있어야 하며 아래 주제 지도 전체에 선수 관계와 기초·응용·심화 진입점을 제공해야 한다. 현재 과제에 필요한 선수만 보완하고 여러 주제를 거친 뒤 재방문할 수 있어야 한다.
- **FR-006**: 아래 13개 주제군을 유한한 범위로 관리하고 기본·응용에서 다룰 범위와 보류·선택 심화를 구분해야 한다. 모든 알려진 알고리즘의 열거·숙달, 문제집 번호순 완주, 자료 간 공통 절대 난도를 요구해서는 안 된다.
- **FR-007**: 난도 상향은 서로 다른 대표 변형 두 개에서 설계·직접 구현·경계 실행·적용 조건과 복잡도 설명을 확인한 뒤 잠정 결정해야 한다. 핵심 힌트가 필요했던 과제는 도움을 구분하고, 도움 없이 수행한 별도 변형으로 상향 근거를 보완해야 한다.
- **FR-008**: 핵심 단계 둘 이상을 새로 배워야 하거나 같은 공백이 두 시도에서 반복되면 해당 선수·간단한 변형으로 보완을 제안해야 한다. 탐색이 계속되면 독립 작업을 유지할 수 있으며 고정 시간 경과를 정답 공개 조건으로 삼아서는 안 된다.
- **FR-009**: 다음 주제 이동은 해당 과제의 설명·구현·경계 검토가 가능하고 다음 주제의 선수가 준비됐을 때 허용해야 한다. 미완료 심화와 재방문 조건을 구분해야 하며, 다른 날 자료 없는 재현 및 새 문제 독립 적용이 확인되기 전에는 장기 숙달로 표현해서는 안 된다.

#### 학습자 주도의 회차

- **FR-010**: 회차마다 목표 하나·선택 이유·완료 기준을 짧게 제시해야 한다. 새 기법은 필요한 설명과 작은 예제 뒤 학습자가 설계·백지 구현·실행·반례 검토를 직접 수행하도록 해야 한다.

- **FR-012**: 독립 작업을 기본 주간 예산의 절반 이상 배정해야 한다. 기본 진행을 연속 한 줄 질문으로 쪼개지 않고 실제 막힌 부분·요청에 맞춰 힌트를 단계적으로 제공한 뒤 전체 과제로 돌아가야 한다. 도움의 단계와 범위를 구분해야 한다.
- **FR-013**: 명시적인 코드 제공·수정 요청 없이 사용자 풀이를 완성 코드로 교체해서는 안 된다. 정답 요청에는 제공할 수 있으나 도움을 기록해야 하고, 입출력 준비 요청은 해당 준비 범위에 한정해야 한다.

### 검토할 학습 방향과 기본값

확정된 조건은 **주 5–7시간, AtCoder 파랑 → 노랑, 별도 ABC 올솔, 장기 Codeforces 빨강, 학습자 직접 구현**이다. 아래의 재방문 구성·상향에 사용할 대표 변형 수·주간 배분·시범 순서는 명세·계획 승인으로 채택한 설계 기준이다. 실제 문서 반영은 작업 목록·검증 가이드에서 확인하며, 이후 사용자의 시범 운영 결과에 따라 조정할 수 있다.

주제를 가로로 한 차례씩 익힌 후 응용·심화로 다시 방문하는 구성을 기본으로 제안한다. 현재 SCC → DAG DP 연결을 마무리한 뒤 DP 응용 → 이분탐색 응용 → 혼합 점검으로 이어가되, 과제가 이어지면 순서를 늦춘다. 과거 자료·설명으로 이미 확인한 기초는 반복하지 않는다. 모든 주제의 기초를 먼저 끝내야 응용에 들어갈 수 있다는 공통 관문도 두지 않는다.

난도는 **과제 내 단계**로 해석한다. 기초는 원리와 표준 구현, 응용은 조건 변형과 모델링, 심화는 복합 기법·증명·최적화다. 서로 다른 주제의 같은 단계가 동일한 절대 난도라는 뜻은 아니다. FR-007의 대표 변형 두 개는 보편적인 숙달 법칙이 아닌 시범 운영 기준이며, 기존의 충분한 실제 증거를 다시 시험하도록 요구하지 않는다.

### 기본 주간 운영과 대체 운영

검토 기본값은 **주 6시간**, 5–7시간 사이에서 가감한다. 각 칸은 설명·시도·검증을 포함한 활동 전체 예산이다. 그중 독립 설계·구현·실행·반례 검토를 절반 이상 확보한다. 문제 수는 풀이 속도에 따라 조정하며 미완료도 그대로 남긴다.

| 활동 | 일반 주 | ABC 대회 주 |
| --- | ---: | ---: |
| 주제 학습·직접 구현 | 180분 | 120분 |
| 혼합 문제 | 90분 | 대회 100분으로 대체 |
| 종료 후 복기·업솔빙 | 혼합·주제 리뷰에 포함 | 80분 |
| 다른 날 재현·반례 검토 | 60분 | 40분 |
| 기록·다음 범위 점검 | 30분 | 20분 |
| 합계 | 360분 | 360분 |

- **5시간 주**: 일반 주의 주제·혼합을 각각 30분 줄인다. 대회 주는 주제·복기 업솔빙을 각각 30분 줄인다. 각각 총 300분이다.
- **7시간 주**: 일반·대회 주 모두 주제 30분과 다른 날 재현 30분을 추가한다. 각각 총 420분이다.
- **대회 빈도 기본값**: 2주에 한 번 실전 또는 미견 virtual을 선택하고, 첫 4주에는 최소 한 번 측정할 기회를 둔다. 대회가 없거나 일정이 맞지 않으면 기존 일반 주로 운영한다. 참가 횟수를 채우기 위한 중복 대회는 요구하지 않는다.
- **대회 길이 변경**: 위 대체표는 ABC 100분 기준이다. ARC·Codeforces 등은 공식 시간을 먼저 반영하고 차이만큼 다른 활동을 줄여 총 예산을 맞춘다. 후속 Codeforces 기준선도 같은 예산 안의 측정이며 추가 숙제가 아니다.
- **도움 요청**: 막힌 위치 확인 → 필요한 관찰·반례 → 핵심 아이디어 설명 → 요청 시 해설·코드의 순서로 필요한 범위만 제공한다. 진행 중인 대회·측정에는 적용하지 않는다. 시간을 재는 것은 배분 점검용이며 강제 해설 타이머가 아니다.

### 첫 4주 시범 운영과 이후 조정

시작일은 개편 적용 후 실제 첫 학습일이다. 아래는 매주 5–7시간 안에서 고르는 주된 과제이며, 각 주의 열을 전부 별도 숙제로 더하지 않는다. 명세 작성일을 학습 시작일로 기록하지 않는다.

| 주 | 주된 학습 목표 | 관찰할 증거와 조정 |
| --- | --- | --- |
| 1주 | 현재 SCC·축약 그래프에서 값 집계와 DAG DP 연결 | 기존 코드에서 이어 직접 설계·구현·실행한다. 미완료면 2주 신규 범위를 줄이고 이어간다. 현재 단계에서 정답 코드를 미리 작성하지 않는다. |
| 2주 | 실제 공백에 맞는 DP 응용 하나와 대표 변형 | 이미 확인한 기초를 반복하지 않는다. 대회가 있으면 대체표를 적용하고 F/G 또는 적정 미견 문제에서 막힌 단계를 관찰한다. |
| 3주 | 이분탐색의 단조성·경계·결정 문제 응용 | 현재 근거로 익숙한 부분은 생략한다. 앞선 과제의 다른 날 재현을 포함하고 필요한 선수 공백만 보완한다. |
| 4주 | 태그 없는 혼합 적용과 운영 검토 | 앞서 측정 기회가 없었다면 미견 ABC 100분을 선택한다. 이미 측정했다면 혼합 문제로 대체할 수 있다. 실제 시간·도움·오류·재현을 보고 다음 회전을 정한다. |

4주 검토에서는 배정 시간과 실제 시간, 시도·검증한 과제, 핵심 힌트 유무, 반복 오류, 다른 날 자료 없는 재현, 미견 문제의 접근 선택을 함께 본다. 예산 초과·미완료가 반복되면 신규 과제 수나 선수 범위를 줄이고, FR-007이 충족되면 변형을 상향한다. 설명을 들었지만 재현 근거가 없으면 완료로 승격하지 않고 재방문을 잡는다. 이후에도 4주 단위로 같은 기준을 적용한다. **4주 내 rating 도달·ABC 올솔은 보장하지 않는다.**

색상 경계는 [S11–S12]를 따른다. 2026-10-19 확인한 AtCoder 안내에서 ABC rated 범위는 0–1999이고 ARC 형식별 범위가 다르다. 노랑 목표 부근에서는 해당 회차의 공식 조건을 다시 확인해야 한다. ABC 올솔 연습은 rating 대상 여부와 별도로 계속할 수 있다. [S13]

- **주제와 선수 관계**: 위 13개 주제군의 기법·단계·필요한 선수·선택 심화·재방문 조건. 학습 완료 목록 자체가 아니다.

- **학습 증거**: 실제 대상 코드·입력·출력·작성자·도움·실행자·온라인 판정과 출처·재현 날짜 및 조건. 미확인 항목을 허용한다.
- **주간 예산과 검토 결과**: 가용 시간·배정/실제 시간·이월·다음 난도 또는 주제 선택. 계획과 실제 성과를 구분한다.
- **목표별 결과**: 플랫폼별 rating, 실전·virtual·업솔빙·재풀이 결과를 각각 날짜·조건·근거와 연결한 사실. 별도 DB 개발을 뜻하지 않는다.

## 성공 기준

### 측정 가능한 결과

아래는 개편 결과를 검토하고 시범 운영의 유용성을 판단할 기준이다. 학습자가 아직 수행하지 않은 시범·풀이 성과가 발생했다고 표시하는 기준이 아니다.

- **SC-001**: 학습자와 조력자가 현재 자료만으로 다음 과제 하나·선택 이유·완료 기준을 설명할 수 있고, SCC 재시작 및 미구현 DP 완료 오기 두 사례를 모두 피한다. (이야기 1)
- **SC-002**: 13개 주제군 모두에 기초·응용·선수·선택 심화가 있으며, 주제 세 개를 임의 선택했을 때 진입·다음 단계·재방문 조건을 모두 찾을 수 있다. (이야기 2)
- **SC-003**: 신규 기법·익숙한 주제·혼합 문제·힌트 요청 네 상황 모두에서 독립 작업과 도움의 범위를 구분할 수 있고, 기본 주간 예산의 50% 이상을 독립 작업에 배정한다. (이야기 3)
- **SC-004**: 일반·대회 주 각각의 5·6·7시간 예시 여섯 개가 복기·기록을 포함해 300·360·420분이며, 이월 사례에서도 7시간을 넘는 의무 분량을 만들지 않는다. (이야기 4)
- **SC-005**: 4주 시범을 검토할 때 주별 실제 시간, 시도한 작업, 도움, 반복 오류, 지연 재현 또는 미확인을 확인하고 다음 회전의 유지·축소·상향 중 하나와 이유를 정할 수 있다. 예정·미실행 주는 그대로 표시한다. (이야기 4)
- **SC-006**: 실전·미견 virtual·업솔빙·기출 재풀이 네 사례를 각각 올바르게 분류하고, AtCoder 1600·2000과 Codeforces 2400+ 목표를 환산이나 올솔 대체 없이 설명할 수 있다. (이야기 6)
- **SC-007**: 코드 존재·샘플 통과·사용자 보고 AC·비공식 제출 기록·같은 날 재구현·다른 날 독립 재현의 여섯 사례에서 확인 범위와 미확인을 모두 구분할 수 있다. (이야기 7)
- **SC-008**: 학습자는 검토용 명세에서 확정 조건과 제안 기본값을 구분하고 방향을 승인하거나 수정 요청할 수 있다. 검토 전 기존 사용자 자료 변경, 자동 학습 완료 기록, 다음 단계 자동 승인은 각각 0건이어야 한다. (이야기 5)

## 가정과 의존성

### 적용 범위와 후속 계획의 책임

- 대상은 이 저장소의 개인 학습자와 학습을 돕는 조력자다. 기존 풀이·개념 노트·대회 복기를 사용하며 새 학습 서비스 구축을 요구하지 않는다.
- 기준 위치는 [ROADMAP](../../ROADMAP.md)의 범위·운영, [STATE](../../STATE.md)의 짧은 현재 위치·다음 행동, [참고 자료](../../docs/REFERENCES.md)의 출처, [학습 스킬](../../.agents/skills/study-algorithms/SKILL.md)의 회차·도움·증거 절차다. 개념·문제·대회 기록은 기존 해당 기록 스킬의 책임을 유지한다.
- 다음 계획 단계는 이 책임 배치에 맞춰 바꿀 문서와 검증 범위를 제시해야 한다. 이 명세 단계에서는 해당 문서나 스킬을 수정하지 않는다. 과거 수치·결과는 날짜가 있는 과거 근거로 보존한다.
- [AGENTS](../../AGENTS.md)의 학습·보존·기록 경계와 공식 검토 게이트를 적용한다. [헌법 파일](../../.specify/memory/constitution.md)은 placeholder 템플릿이며 이번 작업에서 비준하지 않는다. 예시 원칙이나 예시 날짜를 유효한 규칙으로 해석하지 않는다.
- 주 6시간 배분, 격주 측정 기회, 대표 변형 두 개, 첫 4주 주제 순서는 조정 가능한 제안이다. 목표 달성 기한이나 과학적으로 확정된 숙달·해설 공개 기준이라는 가정은 두지 않는다.
- 자료 접근이 실패해도 알려진 코드와 마지막 확인 근거에서 학습을 시작할 수 있다. 최신 통계 재조회와 공식 판정 확인 여부는 별도로 남긴다.

### 출발점의 근거와 미확인 사항

**조사 기준일은 2026-10-19 KST**다. 이번 대화에서 공식 프로필·history JSON과 비공식 AtCoder Problems 제출 자료를 직접 조회하고 원본 응답·조회 영수증을 보관했다. 상세 수치·제출 ID·누적 시간과 자료별 적용 제안은 [조사 근거](research-evidence.md)에서 관리한다.

출발점 요약은 `10o0o`의 Rating **1065 (Provisional)**, 최신 ABC480(2026-10-17)의 performance **1532**다. 비공식 자료에서는 대회 시간 안의 A–E AC 다섯 건을 확인했다. 공식 standings·제출 목록 직접 요청은 HTTP 429로 확인하지 못했으므로 공식 제출 직접 확인이라고 표현하지 않는다. [S01–S04]

현재 파일에는 SCC·축약 그래프 구현과 미구현 `max_coins`가 있다. 로컬 scratch는 다른 기기에 존재한다고 보장할 수 없으므로, 실제 재개 시 파일을 다시 확인하고 남은 DAG DP 연결부터 과제를 정한다. 이 조사에서 코드를 수정·실행하거나 온라인 판정·도움 없는 재현을 새로 확인한 것은 아니다.

누적 제출 시각과 그 차이는 개별 문제의 순수 사고·구현 시간과 같지 않다. 도움 여부, F/G 열람·시도 여부, Codeforces 현재 rating·기준선은 미확인이다. 이는 학습을 막는 추가 답변 요구가 아니며 이후 실제 시도·코드·설명에서 확인한다.
