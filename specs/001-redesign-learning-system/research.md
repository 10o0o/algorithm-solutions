# 계획 연구: 학습 체계 개편

> **과거 설계·검증 자료(2026-10-19).** 현재 재개는 [STATE](../../STATE.md), 수업 운영은 [학습 스킬](../../.agents/skills/study-algorithms/SKILL.md), 채택 근거는 [수업 개선 설계](../../docs/TEACHING_DESIGN.md)를 따른다. 아래의 옛 재개 과제·실행기·승인 단계는 당시 기록이며 현재 지시가 아니다.

기준일: 2026-10-19 KST. [승인된 명세](spec.md)를 기존 문서와 학습 스킬에 반영하기 위한 Phase 0 연구다. 학습 운영은 아직 변경하지 않았다. 명세 단계의 계정 조회·제출 근거는 [research-evidence.md](research-evidence.md)가 담당하고, 이 문서는 설계 선택과 대안을 담당한다.

## 조사 방법과 적용 지침

- 공식 Run `1d02e086`에서 명세 검토의 `choice=approve`, 현재 `plan` 단계를 확인했다. 새 실행이나 브랜치를 만들지 않는다.
- [당시 계획 스킬(퇴역본)](../../.specify/retired/.agents/skills/speckit-plan/SKILL.md)의 연구 위임 절차에 따라 두 읽기 전용 연구를 수행했다. 하나는 기존 문서·기록 호환성, 다른 하나는 학습 자료·시간 배분·측정 조건을 조사했다. 파일 작성은 주 담당자 한 명이 맡는다.
- [헌법 파일](../../.specify/memory/constitution.md)은 예시와 자리표시자가 남은 미비준 템플릿이다. 연구 진입 전 실제 [AGENTS](../../AGENTS.md), [학습 스킬](../../.agents/skills/study-algorithms/SKILL.md), 승인 명세의 보존·학습자 구현·단계 승인·범위 조건을 확인했다. 확정된 헌법으로 간주하지 않는다.
- 외부 자료의 설명과 이 저장소가 채택한 운영 기준을 구분한다. 아래의 시간 비율·변형 수·4주 순서는 외부 자료가 보증하는 학습 법칙이 아니다.

## R01 — 구현 형태와 문서 책임

**결정**: 기존 Markdown과 네 학습·기록 스킬을 사용한다. ROADMAP은 범위·난도 전환·예산, STATE는 짧은 현재 위치, REFERENCES는 자료 출처, 학습 스킬은 회차와 도움 경계, 기록 스킬은 요청한 경험의 저장을 맡는다. 새 프로그램·DB·대시보드·자동 수집기를 만들지 않는다.

**근거**: 기존 [AGENTS](../../AGENTS.md), [ROADMAP](../../ROADMAP.md), [기록 사용법](../../docs/USAGE.md)에서 이 책임 구분을 이미 사용한다. 새 서비스가 없어도 명세의 관찰 가능한 결과를 문서와 실제 사용자 과제로 검증할 수 있다.

**검토한 대안**: 주제별 진도 DB와 자동 제출 수집은 관리 비용·정보 중복·요청 외 개발을 늘린다. 모든 기준을 STATE 하나에 넣으면 재개 문서가 다시 전체 이력과 운영 규칙을 복제한다.

## R02 — 현재 위치와 과거 기록 보존

**결정**: 최신 기준은 이번 대화의 명세 작성 전 조사에서 직접 조회한 2026-10-19 계정 스냅샷이다. 실제 파일을 다시 읽어 `find_scc`·`build_condensation`의 구현과 `max_coins`의 `NotImplementedError`를 확인했다. 다음 학습은 남은 값 집계·DAG DP 연결부터 시작한다. 이번 계획에서는 SCC 풀이와 로컬 scratch를 실행하거나 수정하지 않았다. 기존 단위 검사의 세그먼트 트리 실행은 별도의 저장소 회귀 검사이며 새 학습 성과가 아니다.

STATE를 축약할 때 세그먼트 트리의 상세 근거는 [기존 노트](../../knowledge/data-structures/segment-tree.md)에 연결한다. 기존 STATE에만 있는 과거 관찰은 [내용이 고정된 당시 STATE](https://github.com/10o0o/algorithm-solutions/blob/7c5bf71e96e2fefd3451178470662554d209232e/STATE.md)에 연결한다. 이 revision의 STATE와 현재 작업 전 STATE 내용이 같은지 구현 직전에 대조한다. 당시의 값·미확인·보류 질문을 현재 성과로 바꾸지 않는다.

**근거**: 현재 [STATE](../../STATE.md)는 ABC478·972와 SCC 시작 전 안내를 담고 있어 실제 코드·최신 스냅샷과 다르다. 날짜가 고정된 과거 기록과 현재 재개 요약의 역할을 나누어야 한다. 기록 스킬은 Git 이력만으로 학습자의 새로운 경험을 복원하지 않는다.

**검토한 대안**: `docs/history/`에 STATE 사본을 추가하면 현재 트리에서 읽을 수 있지만 복제와 상대 링크 보정이 필요하다. 원문을 삭제하고 최신 값만 남기면 과거 실행·보류 질문의 근거를 잃는다. 고정 revision 링크와 기존 노트 연결을 최소 변경으로 선택했다.

## R03 — 주제 지도와 난도 조절

**결정**: 명세의 T01–T13을 유한한 범위로 유지한다. 각 주제 안에서 표준 구현 → 조건 변형·모델링 → 복합 기법·최적화로 확장하고, 현재 과제에 필요한 선수만 확인한다. 여러 주제를 거친 뒤 재방문하며, 다른 갈래의 최고 난도 완주를 관문으로 만들지 않는다.

**근거**: [USACO Guide 사용법](https://usaco.guide/general/using-this-guide)은 고정 실라버스가 아니며 모듈 사이 난도 비교와 Python 지원에 한계가 있다고 설명한다. [CSES](https://cses.fi/problemset/)의 분야 구분은 범위 점검에 유용하지만 개인의 학습 순서를 확정하지 않는다.

**검토한 대안**: DP·SCC 등을 하나의 절대 난도 축에 정렬하거나 주제 하나를 끝까지 완주한 뒤 이동하는 방식은 선수 관계가 다른 갈래를 묶는다. 문제집 전체 순회 대신 목적에 맞는 과제를 선별한다.

## R04 — 상향·보완·이동과 도움

**결정**: 서로 다른 대표 변형 두 개에서 추가 핵심 힌트 없이 설계·직접 구현·경계 실행·설명이 확인되면 잠정 상향한다. 핵심 단계 두 개 이상이 새롭거나 같은 공백이 두 시도에서 반복되면 선수나 단순 변형을 보완한다. 과제 설명·구현·경계 검토와 다음 선수 준비가 확인되면 주제 이동을 허용한다. 잠정 배치와 장기 숙달을 분리한다.

**근거**: 이는 승인 명세 FR-007–009의 시범 운영 기준이다. [USACO Guide 연습법](https://usaco.guide/general/practicing)은 적정 난도와 직접 생각한 뒤의 학습·구현을 다루지만, 해설 공개 시점은 여러 작성자가 서로 다르게 권한다. 고정 타이머를 유일한 정답으로 채택할 근거는 없다.

**검토한 대안**: 문제 수·경과 시간·한 번의 AC만으로 승급하면 도움과 실제 공백을 놓친다. 매번 짧은 사전 퀴즈를 반복하면 이미 있는 코드·설명 근거를 활용하지 못한다. 필요한 설명 뒤 충분한 독립 작업을 맡기고, 요청과 관찰한 막힘에 맞춰 도움을 준다.

## R05 — 주 5–7시간과 독립 작업

**결정**: 명세의 일반·ABC 대회 주 5·6·7시간 표를 그대로 구체화한다. 각 활동의 전체 시간과 그 안의 독립 작업 배정을 별도로 표시한다. 모든 활동 합계는 300·360·420분이며 독립 작업은 최소 절반이다. 대회·복기·기록은 합계에 포함한다.

**근거**: 기존 ROADMAP의 9–13시간은 새 시간 제약과 맞지 않는다. 또한 ‘주제 학습’이라는 활동 이름만으로는 설명·힌트를 제외한 독립 시간을 증명할 수 없다. 독립 작업 시간과 도움 없이 해결했다는 성과는 서로 다른 사실이다.

**검토한 대안**: 대회를 기존 시간표에 추가하거나 이월 과제를 다음 주에 누적하면 7시간 상한을 넘긴다. 독립 시간을 활동 전체와 동일시하지 않고 [회차 계약](contracts/learning-session.md)의 배정표로 확인한다. 실제 시간이 줄면 신규 범위를 줄이고 초과·미실행을 그대로 남긴다.

## R06 — 자료 선택과 대회 측정

**결정**: CSES는 대표 구현, [AtCoder DP](https://atcoder.jp/contests/dp/tasks)는 상태·전이, [Typical 90](https://atcoder.jp/contests/typical90)은 주제·컬렉션 내부 난도의 선별 단서, [cp-algorithms](https://cp-algorithms.com/)는 심화 참고로 사용한다. 구체 문제를 제시할 때 현재 노출 여부·선수·제약을 확인한다. 혼합 측정용 문제의 태그·해설·접근법은 시도 전에 공개하지 않는다.

**근거**: DP의 A–Z 26문제나 Typical 90의 90문제·별 1–7은 자료의 구성이다. 이를 모든 주제나 플랫폼의 절대 난도로 환산하지 않는다. Typical 90은 E869120이 기획·출제한 컬렉션으로, AtCoder 자체 제작 자료라고 표시하지 않는다.

**검토한 대안**: ABC480 F/G를 자동으로 미견 문제로 지정하면 미확인 열람 이력을 사실로 바꾼다. 익숙한 문제는 재풀이 또는 일반 연습으로 분류하고 다른 미견 후보를 고른다. 문제 목록을 미리 늘어놓아 혼합 측정의 접근법을 노출하지 않는다.

## R07 — rating과 올솔의 분리

**결정**: AtCoder 1600 → 2000, ABC 실전 올솔, Codeforces 2400+를 별도 목표로 둔다. 실전·미견 virtual·업솔빙·기출 재풀이는 각각의 결과로 남긴다. 새 대회에 참가할 때 해당 회차의 rated 범위·시간·문제 수를 확인한다.

**근거**: [AtCoder rating 안내](https://info.atcoder.jp/overview/contest/rating)와 [Codeforces 공식 공지](https://codeforces.com/blog/entry/20638)는 각 플랫폼의 색상 경계를 설명한다. [AtCoder 대회 안내](https://info.atcoder.jp/overview/contest/algorithm) 및 [2026 ARC 공지](https://atcoder.jp/posts/2026ARC_en?lang=en)는 형식별 참가 조건이 다름을 확인하는 출처다. 이 연구에서 계정 기준선을 새로 갱신한 것은 아니다.

**검토한 대안**: ABC 올솔로 노랑 도달을 대신 판정하거나 두 플랫폼 rating을 환산하면 다른 측정 결과를 혼동한다. Codeforces의 미확인 현재 rating을 새 학습의 선행 조건으로 삼지 않는다.

## R08 — 기록 형식·인터페이스와 검증

**결정**: 새로운 frontmatter 필드나 자동 상태 전이를 만들지 않는다. 기존 개념·문제·대회 노트의 본문에 작성·도움·실행·판정 출처·재현 조건을 적는다. 대회 템플릿과 스킬에 네 결과 분류·문제 수·노출 여부를 보완하고, 일반 설명만으로 저장하지 않는 경계를 유지한다.

**근거**: [문제 템플릿](../../templates/problem-note.md), [개념 템플릿](../../knowledge/template.md), [대회 템플릿](../../contests/template.md)에 이미 증거 기록 공간이 있다. [검사기](../../scripts/validate_notes.py)와 [웹 콘텐츠 처리](../../web/src/lib/content.ts)는 기존 메타데이터·파일 경로를 사용한다. ROADMAP·STATE·스킬·Spec Kit 산출물은 기본 학습 노트 검사 대상이 아니므로 별도 Markdown·상대 링크 검토가 필요하다.

문서 계약은 학습자 요청 → 회차 진행 → 요청한 기록의 입출력을 정의한다. 외부 API나 DB 계약이 아니다. 학습 스킬에 기존 기록 스킬이 참조하는 `종료와 다음 세션` 제목을 복원해 링크를 살리고, 두 기록 스킬까지 불필요하게 수정하지 않는다.

**검토한 대안**: 기존 모든 노트의 메타데이터를 일괄 변경하면 웹·검사기까지 바뀐다. 계획 문서를 학습 노트로 등록하면 학습 경험과 설계를 섞게 된다. 새 회귀 테스트 대신 기존 검사와 문서 시나리오 검토를 사용한다.
