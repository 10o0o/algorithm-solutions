# 문서 책임과 학습 기록 계약

이 계약은 [명세](../spec.md) FR-020–026 및 대회 결과 분류를 후속 문서 개편에 연결한다. 기존 Markdown의 사람 대상 계약이며 새 frontmatter·데이터베이스·자동 기록 기능을 정의하지 않는다. 항목의 의미와 관계는 [개념 모델](../data-model.md)을 따른다.

## 기준 위치와 저장 요청

| 정보·요청 | 기준 위치 또는 동작 | 경계 |
| --- | --- | --- |
| 주제 범위·선수·단계·주간 예산·목표 | [ROADMAP](../../../ROADMAP.md) | 현재 계정 이력·실제 회차 결과의 복제 금지 |
| 현재 위치·남은 질문·다음 행동 | [STATE](../../../STATE.md) | 짧은 재개 문서. 상세 근거는 기존 기록에 연결 |
| 외부 자료의 역할·출처·한계 | [REFERENCES](../../../docs/REFERENCES.md) | 별도 진도·목표 운영표 금지 |
| 회차·힌트·기록 요청 연결 | [학습 스킬](../../../.agents/skills/study-algorithms/SKILL.md) | 자세한 예산/난도표는 ROADMAP 참조 |
| `개념 정리해줘` | 기존 [개념 기록 스킬](../../../.agents/skills/record-algorithm-knowledge/SKILL.md) | 일반 참고 설명과 실제 학습 경험을 구분 |
| `문제 복기해줘` | 기존 [문제 기록 스킬](../../../.agents/skills/review-algorithm-problem/SKILL.md) | 실제 풀이 옆 동일 basename의 노트 |
| `대회/virtual 복기해줘` | 기존 [대회 기록 스킬](../../../.agents/skills/review-algorithm-contest/SKILL.md) | 실제 참가·측정한 종료 회차만 기록 |
| `STATE 반영해` 또는 동등한 위임 | 확인한 현재 범위와 다음 행동만 STATE에 저장 | 풀이·온라인 제출·원격 작업으로 권한 확대 금지 |
| 일반 설명·힌트·`이해했어`·학습 종료 | 대화로 설명/정리 | 별도 저장 위임 없이 파일 작성 금지 |

교육과정 개편은 `review-plan` 승인 후 공식 작업 분해·구현 단계에서 위 기준 문서와 합의된 스킬을 바꾸는 범위다. 이후 모든 학습 회차에 대한 자동 저장 권한이 생기는 것은 아니다. 이미 확인한 요청 범위의 저장을 다시 승인받지는 않는다.

## 기존 형식과 기록 내용

- 개념: `title`, `updated`, `tags` 및 기존 필수 본문 구조를 유지한다.
- 문제: 위 공통 필드와 실제 문제의 `url`, 노트 기준 상대경로 `solution`을 유지한다. 플랫폼 경로와 LeetCode class API·`@lc` 영역을 보존한다.
- 대회: 공통 필드와 실제 대회의 `url`을 유지한다. 참가일과 노트 작성일을 구분한다.
- 도움·실행·판정 출처·재현은 기존 본문 항목에 필요한 만큼 보완한다. 새 사실이 없으면 같은 노트를 다시 복제하지 않는다.

성공 기준 SC-007의 여섯 증거와 FR-020의 새 문제 적용을 같은 ‘완료’ 값으로 합치지 않는다.

| 관찰 | 기록할 수 있는 사실 | 추가 근거 없이 기록할 수 없는 사실 |
| --- | --- | --- |
| 코드 존재 | 대상 파일에 해당 구현이 있음 | 작성자·도움·실행·AC·숙달 |
| 샘플 통과 | 실행자·코드·실행한 샘플의 실제 출력 | 온라인 AC·전체 정확성·사용자 독립 해결 |
| 사용자 보고 AC | 사용자가 해당 판정을 보고함 | 공식 제출 내역 직접 확인 |
| 비공식 제출 자료 | API 출처·회차/시간 필터·기록 ID/판정 | 공식 제출 직접 확인·도움 없는 해결 |
| 같은 날 재구현 | 날짜·추가 자료/도움 여부·실제 검증 범위 | 다른 날 재현·장기 숙달 |
| 다른 날 독립 재현 | 별도 날짜·자료/핵심 도움 없는 구현·검증 | 모든 새 문제에 적용 가능·전체 주제 숙달 |
| 새 문제 적용 | 다른 문제의 노출·접근 선택·직접 설계/구현·도움·실제 검증. 풀이 자료·핵심 도움 없이 수행했음을 확인한 경우에만 독립 적용으로 표시 | 한 번의 적용을 모든 변형·전체 주제의 숙달로 일반화 |

예상 출력은 실제 출력과 분리하고, 에이전트 실행을 사용자의 실행으로 바꾸지 않는다. 누적 AC 시각이나 시각 차이를 문제별 순수 사고 시간으로 쓰지 않는다. 미확인인 항목은 빈칸을 추정해 채우지 않는다.

## 대회 결과의 본문 계약

템플릿의 기본 정보에 실제 회차·참가/측정 일시·전체 출제 문제 수·공식 제한 시간·실제 측정 시간·사전 노출·도움을 기록한다. 문제별 결과에는 판정과 출처를 연결한다. 이미 있는 회차 기록은 병합하고, 다른 날짜의 별도 virtual은 기존 스킬의 구분 규칙을 따른다.

| 결과 분류 | 확정 조건 |
| --- | --- |
| ABC 실전 올솔 | 실제 ABC의 해당 공식 대회 시간 안에 전체 출제 문제 AC. 100분 형식인지 해당 회차에서 확인 |
| 미견 virtual 올솔 | 미견·사전 노출 없음·AI 도움 없음이 확인된 세트에서 전체 문제를 측정 제한 시간 안에 AC |
| 업솔빙 전체 AC | 종료 후 남은 문제까지 전 문제 AC. 도움·완료일·판정 출처를 구분 |
| 기출 재풀이 올솔 | 이미 본 세트의 전체 재풀이 결과·시간·도움이 확인됨. 실전/미견 virtual과 별도 |

‘실전 5/7 → 이후 업솔빙 7/7’은 같은 문서에 두 결과로 남길 수 있다. 업솔빙 AC로 실전 결과를 소급 변경하지 않는다. 도움을 사용한 virtual은 일반 연습으로 분류하고 독립 측정 올솔로 확정하지 않는다. 도움·노출이 미확인이면 미확인으로 남기고 학습은 계속한다.

AtCoder 파랑/노랑과 Codeforces 빨강의 최초 도달은 각각 공식 rating과 날짜·출처로 확인한다. 현재 rating과 과거 도달 이력을 분리한다. performance·문제집 별·ABC 올솔로 rating 도달을 대신 판정하지 않는다. 참가할 대회의 rated 조건은 최신 공식 회차에서 확인한다.

## STATE 축약과 과거 근거 보존

STATE에는 확인일·현재 목표·최신 계정 근거 요약·현재 코드에서 확인한 범위·남은 질문/연결·다음 독립 행동 하나를 둔다. 상세 과거 실행은 기존 지식/문제 노트 또는 [고정 revision의 당시 STATE](https://github.com/10o0o/algorithm-solutions/blob/7c5bf71e96e2fefd3451178470662554d209232e/STATE.md)로 연결한다.

축약 전에 해당 revision과 작업 전 STATE의 내용 일치를 확인한다. 당시의 rating 972·ABC478과 세그먼트 트리 관찰은 날짜가 있는 과거 근거로 유지한다. 최신 1065·ABC480으로 바꾸는 것은 현재 요약이며 과거 성과 수정이 아니다. 상세 [세그먼트 트리 노트](../../../knowledge/data-structures/segment-tree.md)와 보류 질문도 연결해 남긴다.

현재 scratch의 `find_scc`·`build_condensation`은 구현 존재, `max_coins`는 미구현으로 기록한다. 로컬 scratch를 공개 학습 노트의 `solution`이나 상대 링크 대상으로 삼지 않는다. 다른 기기에 파일이 없을 수 있으므로 공유 가능한 [기존 SCC 코드](../../../cses/Planets_and_Kingdoms.py)와 확인한 남은 과제를 함께 사용한다.

이전 학습 이력을 Git에서 새로 추정하거나 새로운 노트로 복원하지 않는다. 고정 revision 링크는 기존 기록의 보존을 위한 것이며, 사용자에게 새 학습 경험이 발생했다는 증거가 아니다.

## 보존·검증·보고

쓰기 직전 관련 status/diff와 현재 내용을 다시 읽고, 저장 후 파일을 다시 읽어 의미를 확인한다. 각 대상은 한 작성자만 수정한다. 사용자 변경·과거 노트·풀이·로컬 입력·`.cph`·환경·라우터 설정을 덮지 않는다. 기기 절대경로·인증 정보·사생활을 새 문서에 넣지 않는다.

기존 노트 검사기는 기록 형식용이다. ROADMAP·STATE·스킬·Spec Kit 문서를 이 스키마에 맞추거나 학습 노트로 등록하지 않는다. 변경 문서의 상대 링크·앵커·의미는 별도로 검토한다. 웹 콘텐츠 메타데이터·코드 경로와 공개 노트의 관계는 보존한다.

완료 보고에는 로컬 저장, 실행한 검사와 실제 결과, 미검증 범위, 다음 단계의 승인 상태를 구분한다. 기록 저장이나 계획 승인만으로 커밋·push·온라인 제출·배포하지 않는다. 계획 산출물 작성과 향후 운영 개편·실제 시범 수행을 다른 상태로 보고한다.
