# 학습과 증거의 개념 모델

이 문서는 [승인 명세](spec.md)의 학습 단위를 설명한다. DB·새 파일 형식·자동 진도 관리 기능을 요구하지 않는다. 아래 항목은 기존 Markdown 본문과 상대 링크로 표현하며, 모르는 값은 `미확인` 또는 기존 형식의 `unknown`으로 남긴다. 과거 노트 전체를 이 형식으로 변환하지 않는다.

## 관계와 기준 위치

```text
주제와 선수 관계 → 학습 과제 → 실제 시도 증거 → 재현 또는 새 문제 적용
                       ↑             ↓
                  주간 시간 예산 ← 4주 검토의 관찰

플랫폼 rating 결과 / 대회 결과 → 각 목표의 근거
```

한 과제가 여러 주제를 사용할 수 있고, 한 과제에 여러 시도·도움·실행이 있을 수 있다. 목표 결과는 과제 파일의 존재나 예산 배정에서 파생되지 않는다. 기준 문서의 책임은 [기록 계약](contracts/document-records.md)에 둔다.

## 1. 주제와 선수 관계

| 항목 | 의미와 검증 규칙 |
| --- | --- |
| 식별과 범위 | 명세의 T01–T13. 하위 기법과 기본/응용/선택 심화를 구분한다. |
| 단계 | 해당 주제 안의 기초·응용·심화. 서로 다른 주제의 동일 단계는 절대 난도가 아니다. |
| 선수 | 현재 과제에 필요한 개념·구현. 관계없는 주제의 완주를 추가하지 않는다. |
| 진입 근거 | 현재 코드·설명·실제 결과 또는 필요한 최초 설명. 과거 이력의 재답변을 강제하지 않는다. |
| 다음 선택 | 유지·상향·선수 보완·다른 주제 이동·선택 심화 보류. 이유와 근거를 연결한다. |
| 재방문 조건 | 다른 날 재현, 새 문제 적용, 관찰한 반복 오류, 다음 응용에서 필요한 선수 중 하나 이상. |

정적 범위·판단 기준은 ROADMAP, 현재의 짧은 잠정 배치는 STATE, 세부 학습 경험은 요청해 저장한 기존 노트에 둔다. 13개 주제 전체에 자동 완료 플래그를 만들지 않는다.

## 2. 학습 과제

| 항목 | 의미와 검증 규칙 |
| --- | --- |
| 목표와 이유 | 이번 작업에서 확인할 목표 하나, 지금 선택한 이유, 완료 기준. |
| 방식 | 새 기법 학습·주제별 재현·혼합 연습·대회/측정. 방식에 따라 사전 기법 공개와 도움 경계가 달라진다. |
| 대상 | 실제 문제 URL·기존 코드·노트. 공유 노트의 코드 링크는 추적되는 플랫폼 풀이를 사용한다. |
| 노출 | 미견 확인·기출/해설 노출·미확인. 미확인은 미견 측정의 성공 근거가 아니다. |
| 현재 범위 | 이미 구현한 부분, 남은 설계·구현·검증, 실제로 막힌 위치. |
| 예산 | 이번 주 안의 배정 시간. 과제 하나가 여러 회차·주에 이어질 수 있다. |

과제 상태를 표현할 때는 아래 의미를 사용한다. 이를 저장하는 새 필수 필드나 자동 전이는 만들지 않는다.

| 전환 | 필요한 사실 | 의미하지 않는 것 |
| --- | --- | --- |
| 예정 → 시도 중 | 실제로 시작한 설명·설계·코드 등의 관찰 | 계획만으로 수행했다고 기록하지 않음 |
| 시도 중 → 보류·이월 | 남은 범위와 다음 행동, 실제 시간 또는 미확인 | 실패·완료·숙달로 바꾸지 않음 |
| 시도 중/보류 → 현재 과제 확인 | 해당 완료 기준의 설명·구현·경계 검토 근거 | 온라인 AC·추가 도움 없는 해결·전체 주제 숙달과 별개 |
| 현재 과제 확인 → 다음 선택 | 상향·이동·재방문 기준에 맞는 증거 | 하나의 성공을 모든 변형의 숙달로 확대하지 않음 |

## 3. 실제 시도 증거

| 항목 | 의미와 검증 규칙 |
| --- | --- |
| 날짜와 대상 | 관찰일, 상대 코드 경로·확인 가능한 버전, 문제/노트 링크. 사생활·기기 절대경로는 넣지 않는다. |
| 작성과 도움 | 사용자 작성·힌트 후 작성·AI 제공/수정·미확인. 도움의 시점과 영향을 받은 부분을 기록한다. |
| 설명 | 적용 조건·정당성·상태/불변식·복잡도 중 실제 확인한 범위. |
| 실행자와 환경 | 사용자/에이전트/미확인, 실제 사용한 Python·저지 환경 등 필요한 범위. |
| 입력과 출력 | 사용한 샘플·반례 범위, 예상값과 실제 출력의 구분, 통과/불일치/미실행. |
| 온라인 판정 | AC/WA/TLE 등 확인한 값 또는 미확인과 출처. 공식 직접 확인·사용자 보고·비공식 자료를 별도로 표시한다. |
| 시간 | 실제 사용한 시간 또는 미측정. 대회 시작 후 누적 제출 시각은 순수 사고·구현 시간으로 환산하지 않는다. |

도움의 단계는 관찰 질문·반례, 부분 설명, 핵심 아이디어, 해설·코드 등으로 기술한다. 숫자 하나로 작성 독립성을 판정하지 않는다. 최초 개념 설명과 특정 과제의 핵심 풀이 힌트도 구분한다.

## 4. 재현과 적용

재현은 기존 증거를 덮는 ‘완료’ 값이 아니라 날짜가 있는 추가 관찰이다.

| 유형 | 필요한 조건 |
| --- | --- |
| 같은 날 재구현 | 같은 세션/날짜, 추가 도움·자료 사용 여부, 실제 대상과 결과 |
| 다른 날 재현 | 별도 날짜, 자료와 핵심 도움 없이 직접 구현했는지, 실제 검증 결과 |
| 새 문제 적용 | 기존 풀이와 다른 문제, 노출 여부, 접근 선택·정당성·구현과 도움 |

대표 변형 두 개의 잠정 상향은 별도 과제의 근거를 연결해 판단한다. 같은 문제를 두 번 실행한 것은 서로 다른 변형 두 개가 아니다. 핵심 힌트가 필요한 변형은 도움 없는 별도 변형으로 상향 근거를 보완한다. 다른 날 재현과 새 문제 독립 적용이 없으면 장기 숙달이라고 표현하지 않는다.

## 5. 주간 예산과 4주 관찰

| 항목 | 의미와 검증 규칙 |
| --- | --- |
| 예산 | 가용 300/360/420분, 일반/대회 주, 활동별 전체 배정과 그 안의 독립 작업 배정 |
| 독립 작업 | 사용자가 직접 설계·구현·실행·반례를 검토하는 시간. 설명·AI 코드 작성 시간과 중복 계산하지 않는다. |
| 실제 시간 | 관찰하거나 사용자가 보고한 값·근사 여부·미측정. 계획값을 복사해 실적으로 만들지 않는다. |
| 이월 | 남은 작업과 다음 주에 줄일 신규 범위. 주 7시간 초과의 의무 분량을 만들지 않는다. |
| 검토 | 실제 시간·도움·반복 오류·다른 날 재현 또는 미확인을 근거로 유지·축소·상향을 선택한다. |

기본 운영표는 ROADMAP 한 곳에서 관리한다. 주간·4주 검토는 대화와 기존 노트의 확인된 근거를 모아 수행하고, 저장 요청이 있으면 해당 개념·문제·대회 기록 및 짧은 STATE 요약에만 반영한다. 별도 세션별 노트·주제별 진도 DB를 자동 생성하지 않는다. 기록이 없는 주는 미실행·미측정을 구분하며 데이터를 만들어 채우지 않는다.

독립 작업에 시간을 배정한 사실과 특정 문제를 도움 없이 해결한 사실은 다르다. 계획·실제 독립 시간·작성 도움·판정·재현을 각각 유지한다.

## 6. 목표와 결과

| 결과 | 필요한 항목과 판정 조건 |
| --- | --- |
| 플랫폼 rating | AtCoder/Codeforces, 공식 rating·확인일·공식 출처. 과거 최초 도달과 현재 rating을 분리한다. 단일 performance는 도달 근거가 아니다. |
| 대회 참가/측정 | 실제 회차·진행 일시·전체 문제 수·공식 제한 시간·측정 시간·사전 노출·도움·판정 출처 |
| 올솔 결과 | 실전·미견 virtual·업솔빙 전체 AC·기출 재풀이를 구분하고, 해당 조건의 전 문제 AC를 확인한다. |

같은 대회 기록에 ‘100분 내 5/7’과 ‘이후 업솔빙 7/7’이 함께 있을 수 있다. 후자의 성공으로 전자의 결과나 참가 조건을 덮지 않는다. 미확인 도움·노출이 있으면 독립 측정 확정은 보류하지만 일반 학습은 계속할 수 있다.

## 호환성과 현재 출발점

기존 `title/updated/tags`, 문제의 `url/solution`, 대회의 `url`을 유지한다. 추가 개념은 본문으로 표현한다. 기존 노트에 필요한 사실만 병합하고 과거 도움·판정을 다시 추정하지 않는다.

현재 출발점은 2026-10-19 스냅샷의 1065·ABC480, 구현된 SCC·축약 그래프, 미구현 DAG DP다. scratch의 존재를 다른 기기의 공유 재개 보장으로 사용하지 않는다. 상세 수치·확인 한계는 [명세 단계 조사](research-evidence.md), 재개·기록의 동작은 [계약](contracts/document-records.md)에서 확인한다.
