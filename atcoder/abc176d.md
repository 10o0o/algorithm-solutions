# ABC176 D - Wizard in Maze

## 핵심 요약

상하좌우의 길로 걷거나 현재 칸을 중심으로 한 5×5 범위의 길로 워프해 목적지에 도착하는 최소 워프 횟수를 구한다. 걸어서 연결된 칸들을 하나의 구역으로 묶고, 워프가 가능한 구역 사이에 비용 1의 간선을 만든 뒤 최단 거리를 구했다.

격자는 최대 1000×1000이며, 워프의 출발점과 도착점은 모두 길이어야 한다. 워프 중간에 있는 벽은 이동을 막지 않는다. 목적지에 도달할 수 없으면 -1을 출력한다.

## 접근과 불변식

1. BFS로 상하좌우의 길을 탐색해 각 칸에 구역 번호를 부여한다. 방문 표시를 큐에 넣을 때 하므로 같은 칸을 중복 등록하지 않는다.
2. 각 길 칸에서 행·열 차이가 각각 -2부터 2인 칸을 확인한다. 다른 구역의 길이면 두 구역을 연결하며, 집합으로 중복 간선을 합친다.
3. 출발·도착 좌표를 구역 번호로 바꾸고 다익스트라를 실행한다. 거리 배열은 해당 구역까지 필요한 최소 워프 횟수다.

같은 구역 안에서는 워프 없이 어느 칸으로든 이동할 수 있다. 따라서 구역 안의 진입 위치를 따로 저장하지 않아도 다음 워프의 출발점까지 걸어갈 수 있다. 실제 워프는 구역 사이의 간선 하나에 대응하고, 구역 경로의 각 간선도 실제 워프로 실현할 수 있어 압축한 그래프의 최단 거리가 답이 된다.

이 정당성은 복기를 작성하며 에이전트가 정리한 설명이다. 사용자가 직접 정당성과 복잡도를 설명한 사실까지 확인한 것은 아니다.

## 풀이와 복잡도

현재 저장된 풀이는 구역 탐색에 BFS, 구역 그래프의 최단 거리 탐색에 다익스트라를 사용한다. 힙에서 꺼낸 현재 구역의 이웃을 확인하고, 더 짧은 거리를 발견하면 거리 배열과 힙을 갱신한다.

구역 수를 K, 중복 제거 후 구역 간 간선 수를 E라 하면 구역 분리와 간선 생성은 평균적인 집합 연산을 기준으로 O(HW)다. 각 칸에서 확인하는 후보는 최대 25개다. 다익스트라를 포함한 시간 상한은 O(HW + (K + E) log K), 공간은 O(HW + K + E)다.

압축 후의 모든 간선 비용은 1이므로 일반 BFS로도 탐색할 수 있다. 큐가 거리 0, 1, 2 순서로 처리하므로 처음 발견한 거리가 최단 거리이며, 탐색 시간은 O(K + E)다. 이 대안은 에이전트가 설명과 함수 코드를 제공하고 임시 실행으로 검증했다. 사용자의 BFS 재구현은 미확인이며 현재 풀이 파일은 다익스트라 버전이다.

## 실패와 도움

- 미로 입력에 `input().strip().split()`을 사용해 한 행 전체가 리스트 원소 하나가 됐다. 에이전트가 공백 분리와 문자 분리의 차이를 실행 결과로 설명하고 `list(input().strip())`을 제시했다. 출발·도착 좌표의 변수 순서도 함께 교정하도록 안내했다.
- 다익스트라에서 `graph[start]`를 반복해 시작 구역의 이웃만 확인했다. 에이전트가 아래 반례를 실행해 실패를 확인하고, 힙에서 꺼낸 현재 구역에 해당하는 `graph[node]`를 사용하도록 설명했다.
- 구역 번호와 그래프를 출력하는 디버그 문장이 남아 있었다. 제출 출력에서 제거하도록 안내했고, 현재 파일에서는 제거된 것을 확인했다.

구역 분리·워프 간선 구성·다익스트라 본문은 사용자가 구현했다. 위 입력 처리와 이웃 참조에는 수정 예시·설명이 제공됐으며, 이 대화에서 에이전트가 사용자 풀이 파일을 직접 편집하지는 않았다.

## 반례

```text
1 5
1 1
1 5
.#.#.
```

기대 출력:

```text
2
```

길 세 칸은 서로 다른 구역이며 구역 그래프는 0 ↔ 1 ↔ 2다. 수정 전에는 구역 1을 꺼내도 구역 0의 이웃만 확인해 실제 출력이 -1이었다. 현재 코드의 실제 출력은 2다.

저장소 루트에서 재현:

```bash
printf '1 5\n1 1\n1 5\n.#.#.\n' | uv run --frozen python atcoder/abc176d.py
```

## 검증과 학습 위치

- 2026-10-24 CPython 3.12.14에서 에이전트가 현재 풀이 파일을 실행했다. CPH에 저장된 공식 예제 4개의 출력은 각각 1, -1, 0, 2였고 위 반례는 2였다. 다섯 입력 모두 기대 출력과 일치했다.
- 온라인 판정: 사용자가 같은 대화에서 AC를 보고했다. 공식 제출 내역을 직접 조회하거나 제출 코드와 현재 파일을 대조하지는 않았다.
- 사전 문제·해설 노출, 풀이 시간, 자료 없는 별도 날짜 재현은 미확인이다. 이번 결과는 수정 설명을 받은 일반 연습의 구현·로컬 검증·사용자 보고 AC로 구분하며, 도움 없는 해결이나 장기 숙달로 표시하지 않는다.
- 로드맵의 T06에서 구역 그래프 모델링과 최단 거리의 새 문제 적용을 확인했다. 이후 ABC061 D의 벨만–포드 반복 갱신과 무한 증가 판정을 소개했으며, 그 문제의 구현은 미확인이다. 다음 재개 위치는 [STATE](../STATE.md#다음-독립-행동)에 둔다.
