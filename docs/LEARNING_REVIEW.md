# 학습 진행과 로드맵 점검

**수업 개선 전 검토 기록.** 아래 다음 행동은 당시 제안이다. 현재 재개 선택은
[STATE](../STATE.md), 회차 운영은 [학습 스킬](../.agents/skills/study-algorithms/SKILL.md),
반영된 개선 근거는 [수업 개선 설계](TEACHING_DESIGN.md)를 따른다.

2026-10-23에 이 대화의 학습 과정과 현재 저장된 코드를 대조하여 누락된 기록을 정리했다. 문제별 정확한 수행일·풀이 시간은 측정하지 않았으므로 문서 갱신일을 풀이 완료일로 사용하지 않는다. 범위·운영 기준은 [로드맵](../ROADMAP.md), 실제 다음 행동은 [STATE](../STATE.md), 개별 접근·실패·도움·판정은 아래 문제 복기에 둔다.

## 판단

주제 흐름은 계획에 맞는다. SCC·DAG DP에서 DP 응용, 이분 탐색, 누적합·스위핑, 힙·그리디를 거쳐 다익스트라·상태 그래프·0-1 BFS로 연결했다. 각각 T05, T04, T01, T12/T03/T08, T06의 범위다. 앞서 배운 힙과 상태 모델을 다음 과제에 연결한 이유도 일관적이다.

다만 운영에는 보완이 필요하다. 설명과 교정 뒤 새 문제로 이동한 사례가 많아, 로드맵이 요구하는 자료 없는 재현·태그 없는 접근 선택·사용자의 정당성 설명을 충분히 확인하지 못했다. 현재 근거는 주제 학습과 도움 후 구현의 진전이며, 목표 rating 도달이나 장기 숙달의 근거는 아니다. 다음 회차는 새 기법을 연달아 추가하기보다 최근 구현의 독립 재현 하나를 우선한다.

## 대화에서 확인한 진행

| 주제 | 다룬 과제 | 확인한 범위 |
| --- | --- | --- |
| T05 → T04 | [Coin Collector](https://cses.fi/problemset/task/1686/) 로컬 실습 | SCC별 동전 합·축약 DAG·위상순서 DP를 구현·검토했다. 사용자에게서 진입차수 0 이후 DP 값이 확정되는 이유의 설명을 확인했다. 입력·코드 설명·일부 수정 도움도 있었다. 온라인 AC는 미확인이다. |
| T04 | [DP E - Knapsack 2](https://atcoder.jp/contests/dp/tasks/dp_e), [DP F - LCS](../atcoder/dpf.md) | 가치별 최소 무게 DP를 로컬 파일에 구현했다. LCS는 사용자 요청으로 모범 구현을 제공하고 역추적을 설명했다. 둘 다 온라인 AC는 미확인이다. |
| T01 | [Yokan Party](../atcoder/typical90a.md), [Array Division](../cses/Array_Division.md), [2-variable Function](../atcoder/abc246d.md), [Longest X](../atcoder/abc229d.md) | 최대 참·최소 참 탐색, 그리디 판정, 열거 범위, 윈도 경계를 다뤘다. Longest X는 사용자 수정 후 AC 보고가 있다. |
| T01 / T12 | [Count Interval](../atcoder/abc233d.md), [Online games](../atcoder/abc221d.md) | 누적합 빈도표와 조회 순서, 좌표 압축·차분 배열·반열린 구간을 다뤘다. Online games는 사용자 구현 후 AC 보고가 있다. |
| T03 / T08 | [Packing Under Range Regulations](../atcoder/abc214e.md), [Printing Machine](../atcoder/abc325d.md), [Querying Multiset](../atcoder/abc212d.md) | 현재 가능한 후보와 우선순위를 분리했다. Packing은 모범 코드 제공, Printing은 흐름·일부 코드 설명 후 사용자 구현과 교정, Multiset은 사용자 누적 가산 설계 후 삽입 보정을 교정했다. |
| T06 | [Super Takahashi Bros.](../atcoder/abc340d.md), [Train](../atcoder/abc192e.md) | 기본 다익스트라와 시간에 따른 대기를 다뤘다. 두 문제는 사용자 AC 보고가 있다. Train 오류의 최종 수정은 사용자가 수행했다. |
| T06 / T08 | [Flip Edge](../atcoder/abc395e.md), [Crystal Switches](../atcoder/abc277e.md) | 정점·반전 상태를 함께 저장하는 모델과 0-1 BFS를 설명한 뒤 사용자가 구현했다. 인접 목록 접근, 도착 정점 거리 갱신, 무방향 구성·초기화·도달 불가 처리를 에이전트가 교정했다. 온라인 AC는 미확인이다. |

온라인 AC는 **사용자 보고 네 문제**로 구분했다. 공식 제출 원문과 현재 파일을 대조하거나 최신 계정 기록을 조회한 작업은 아니다. 다른 문제의 `완료`·`다음`·로컬 통과를 AC나 무힌트 해결로 해석하지 않는다.

## 로컬 실습과 보류 범위

Coin Collector와 Knapsack 2의 실제 구현은 Git에서 제외된 로컬 연습 파일에 있다. 공개 플랫폼 풀이와 같은 이름의 복기를 만들 수 있는 공유 코드가 아직 없어, 해당 진행은 이 문서에만 요약했다. 로컬 원본을 이동·복사·덮어쓰지 않았다.

- Coin Collector: 현재 실습은 반복형 Kosaraju, 성분별 동전 합, 중복을 집합으로 합친 축약 간선, Kahn 순서 DP를 포함한다. 동기화 검증에서 두 방의 SCC를 거쳐 나머지 방으로 이어지는 입력의 기대값 28을 확인했다. 기존 [공유 SCC 코드](../cses/Planets_and_Kingdoms.py)를 Coin Collector 전체 구현으로 혼동하지 않는다.
- Knapsack 2: 실제 입력을 읽는 로컬 작업 파일에 2차원 가치별 최소 무게 DP가 있다. 별도로 준비했던 빈 함수 파일의 존재를 구현 결과로 쓰지 않는다. `3 8`과 물건 `(3,30), (4,50), (5,60)`의 기대값 90을 확인했다. 상태 설계·출력 교정 설명이 있었고 독립 숙달은 미확인이다.
- 출발·도착이 고정된 SCC 변형은 사용자가 다음으로 넘어가길 요청해 보류했다. 준비된 코드에 해당 조건이 제대로 반영되었다고 기록하지 않으며 필수 재개 과제로 강제하지 않는다.
- 세그먼트 트리 리프 배치에 관한 이전 보류 질문은 [해당 노트](../knowledge/data-structures/segment-tree.md#자료구조-묶음에서-이어갈-범위)에 유지한다.

## 계획과 실제 운영의 차이

| 로드맵 기준 | 이 대화에서 확인한 실제 | 이번 조정 |
| --- | --- | --- |
| 하나의 충분한 과제 → 구현 → 실행 → 리뷰 | 사용자가 직접 구현했고 실제 코드·반례를 검토했다. 일부는 핵심 설명·모범 코드·에이전트 교정이 포함됐다. | 도움 후 구현과 독립 구현을 구분해 문제 복기에 남긴다. |
| 조건·불변식·정당성·복잡도까지 확인 | SCC의 위상순서 설명은 확인했다. 이후에는 에이전트 설명과 로컬 통과 뒤 바로 이동한 경우가 많았다. | 최근 과제 하나의 재현에 설명과 반례 실행을 함께 묶는다. 연속된 한 줄 퀴즈로 바꾸지 않는다. |
| 서로 다른 변형 두 개를 추가 핵심 도움 없이 수행하면 잠정 상향 | 변형은 여러 개지만 기법을 먼저 공개했고 설명·교정이 있었다. 자료 없는 독립 적용 두 건의 근거는 부족하다. | 현재 주제를 완전 숙달로 올리지 않고 구현·모델링의 반복 오류를 보완한다. |
| 다른 회차 재현과 태그 없는 혼합 연습 | 이 대화에서 별도로 확인한 재현·혼합 측정 기록이 없다. | 다음 기본 행동을 0-1 BFS 재현으로 두고, 이후 태그 없는 문제 하나로 선택 능력을 확인한다. |
| 총 주 5–7시간, 독립 작업 최소 절반 | 실제 총 시간과 독립 작업 시간은 미측정이다. 과제 수를 시간으로 환산할 수 없다. | 다음 회차의 가능 시간과 실제 사용 시간을 기록 요청 범위에서 확인한다. 계획 예산을 수행 시간으로 채우지 않는다. |
| 격주 실전/virtual, 첫 4주에 측정 기회 | 이 대화에는 새 실전·미견 virtual 수행 증거가 없다. | 다음 측정은 주간 예산 안의 학습을 대체하도록 잡는다. 과거 문제·해설 노출과 도움 여부부터 구분한다. |

## 목표와 현재 판단의 한계

중간 목표는 AtCoder 파랑 1600 → 노랑 2000, 별도 목표는 ABC 실전 올솔, 장기 목표는 Codeforces 빨강 2400+다. 이번 점검은 이 세 목표로 가는 알고리즘 학습 경로를 기준으로 했다.

학습한 주제는 목표를 위한 기초·응용 범위에 해당한다. 그러나 현재 rating과 대회 성과가 얼마나 변했는지는 이 기록으로 판단할 수 없다. 2026-10-19의 rating 1065와 performance 1532는 당시 확인값이며 최신 계정 조회가 아니다. Codeforces 기준선과 새 대회 시간 배분도 미확인이다. 기록의 부재를 사용자가 대화 밖에서 활동하지 않았다는 사실로 해석하지 않는다.

## 다음 한 회차

아래는 2026-10-23 점검 당시의 재현 제안이며, 현재의 중단 상태와 재개 시 과제 선택은 [STATE](../STATE.md#다음-독립-행동)를 따른다.

기본 과제는 **현재 풀이와 복기를 닫고 Crystal Switches를 별도 로컬 파일에 재구현하는 것**이다. 이미 본 문제이므로 기출 재현으로 분류하며 미견 측정으로 부르지 않는다. 사용자 코드 원본은 유지한다.

완료 기준은 다음을 하나의 작업으로 확인하는 것이다.

1. `(정점, 반전 여부)`의 거리와 시작 상태를 정의한다.
2. 이동의 갱신 대상, 양방향 간선, 무료 전환과 이동의 덱 삽입 위치를 구현한다.
3. 스위치 없음·시작점 스위치·도달 불가·반대 방향 이동을 직접 실행한다.
4. 무료 전환을 앞에 넣는 이유와 `O(N + M)`의 근거를 짧게 설명한다.

그 다음에는 알고리즘 이름을 먼저 주지 않는 혼합 문제 하나로 접근 선택을 확인한다. 추가 핵심 도움이 필요하면 해당 공백을 보완하고, 충분하면 미진행 주제나 다음 최단 경로 변형으로 이동한다. 심화 전체 완주를 새로운 관문으로 만들지 않는다.

## 이번 동기화의 검증

CPython 3.12.14에서 공유 풀이 14개의 현재 CPH 입력 37개와 문제별 핵심 입력 14개, 로컬 실습 입력 2개를 다시 실행했다. 모두 기대값과 일치했다. LCS는 예제 답과의 문자열 일치 대신 최적 길이와 부분 수열 조건을 확인했다. 이는 2026-10-23 현재 코드의 로컬 검증이며 온라인 판정이나 독립 이해를 증명하지 않는다.

문제 복기 14개와 이 검토 문서는 메타데이터·파일 링크 검사를 통과했고, STATE·ROADMAP의 로컬 링크와 앵커도 확인했다. 배포 하위 경로를 적용한 로컬 웹 빌드와 검색 색인 생성을 확인했다. 풀이·로컬 원본·CPH 데이터 157개 파일의 SHA-256은 작업 전후 동일했다.
