# 알고리즘 수업 개선 구현 계획

**2026-10-23 운영 문서 반영·구현 검증 완료.** [수업 개선 설계](TEACHING_DESIGN.md)를 현재 학습 스킬·로드맵·재개 기록에 반영했다. 아래 작업 순서와 기준에 따른 실제 결과는 [실행 결과](#실행-결과)에 둔다. 학습은 계속 중단 상태이며, 이후 학습 효과는 미관찰이다.

구현 결과는 새 앱이나 학습 관리 시스템이 아닌 기존 운영 문서의 개편이다. 강사가 막힌 단계를 판단하고 필요한 도움을 제공한 뒤 전체 풀이를 학습자에게 돌려주는 흐름을 명확하게 만든다. AtCoder 목표, 주 5–7시간, 학습자 직접 구현, 요청형 모범 코드 제공은 유지한다.

## 작업 순서와 의존성

`I01 기준선 확인 → I02 학습 스킬 → I03 로드맵 → I04 재개 기록 → I05 참고 자료 → I06 통합 검증 → I07 적용 상태와 결과 보고` 순서로 진행한다. 각 파일은 한 작성자가 수정한다. 기존 스킬이 이미 충족하는 행동은 I02에서 유지하고 필요한 정리만 한다.

### Task 1: I01 현재 파일과 행동 기준선 확인

1. `git status --short`와 관련 diff를 확인한다. 이미 수정된 ROADMAP·STATE와 미추적 설계·복기 파일을 초기 작업 상태로 보존한다.
2. 실제 적용 시점의 STATE·학습 스킬·설계와 해당 코드를 다시 읽는다. 이 계획 작성 뒤 사용자가 수정한 내용이 있으면 최신 내용을 기준으로 작업 범위를 조정한다.
3. 변경 대상의 원문과 보호할 풀이·로컬 실습·CPH의 해시를 저장소 밖 임시 위치 또는 세션 내에 보관한다. 원본 파일을 이동하거나 덮어쓰는 백업 방식은 쓰지 않는다.
4. 아래 C01–C09를 기존 지침에 대조하고, 이미 충족하는 행동과 실제로 빠진 조건을 구분한다. 읽기 검토를 실제 에이전트 응답 실험으로 보고하지 않는다.

**산출물:** 변경할 문장·유지할 문장, 현재 작업 상태, 스킬 수정 전에 확인한 행동 검토 결과.

학습 스킬의 행동 문구를 변경할 때는 `writing-skills`의 선행 행동 검증을 적용한다. 관찰된 실패가 있는 핵심 상황을 골라, 공통 지침만 있는 경우·기존 스킬·후보 스킬을 구분하고 문구 비교는 각 조건에서 독립된 맥락으로 5회 이상 확인한다. 구현 순서는 기존 응답 관찰 → 실패 원인에 맞는 최소 수정 → 같은 조건의 후보 응답 검토다. 단어 포함 여부만 세지 않고 실제 응답을 읽는다.

기존 응답이 이미 적절하고 재현할 실패도 없으면 그 행동의 새 규칙 추가는 생략한다. 모든 상황에 새 금지 문장을 붙이거나 실패 결과를 만들어내지 않는다. 필요한 독립 에이전트 검증은 실제 스킬 수정 단계에서 해당 스킬의 위임 절차로 수행하며 사용자에게 학습 과제로 넘기지 않는다. 실제 수행 범위는 아래 실행 결과에서 구분한다.

### Task 2: I02 학습 스킬의 대응 흐름 통합

`name`, 기존 한국어 호출 표현, 기록 스킬 연결, 증거·기록 권한은 유지한다. 일상 수업에서 매번 읽을 수 있도록 기존 중복 문장에 통합하며 설계서 전체를 삽입하지 않는다.

| 현재 위치 | 구체적인 편집 | 확인할 행동 |
| --- | --- | --- |
| `재개 위치와 과제 선택` | 최신 코드·성과를 재사용하고 현재 공백과 연결되는 과제 하나를 고르는 기준을 정리한다. | 오래된 STATE만 보고 기초부터 다시 시작하지 않는다. |
| `한 회차의 학습`의 수업 방식 | 새 기법·혼합·다른 날 재현·실전 측정의 제공 정보와 독립 시도를 짧게 구분한다. | 새 기법은 설명부터, 혼합은 접근 선택부터 진행한다. |
| 같은 절의 막힘 대응 | 문제 의미·새 기법·정당성·상태와 코드·단순 문법·검증 공백에 대한 대응표를 필요한 범위로 통합한다. | 모델 오해에는 작은 사례를, 구현 오류에는 실제 전이 추적을 제공한다. |
| 같은 절의 리뷰·수정 | 최신 파일 → 접근 타당성 → 작은 반례 → 첫 잘못된 판단과 관련 수정 → 좁은 검증의 순서를 명시한다. | 참고 풀이와 다른 타당한 접근을 보존한다. |
| 진행 요청 대응 | `완료`, `이해가 안 돼`, `모범 코드`, `다음`, `세팅만`, `중단`의 행동을 기존 원칙에 통합한다. | 사소한 위임 수정은 처리하고, 코드 요청에는 제공하며, 다음 이동과 중단을 존중한다. |

추가 문구는 관찰 가능한 조건과 행동으로 쓴다. 예를 들어 “사용자가 같은 설명 뒤에도 이해가 어렵다고 하면, 시간표·상태표·이동 예시로 표현을 바꾼 뒤 전체 구현으로 돌아간다”처럼 정한다. “충분히 이해했는지 항상 확인한다” 같은 문장으로 추가 퀴즈 의무를 만들지 않는다.

한 줄 수정이 핵심 불변식이면 의미와 반례를 함께 설명한다. 사용자가 맡긴 수정은 기존 위임 안에서 처리하고, 도움의 영향을 구분한다. 수정량이 작다는 이유로 핵심을 생략하거나 같은 승인을 반복해서 묻지 않는다.

**완료 기준:** C01–C09의 대응을 스킬에서 찾을 수 있고, 재현된 실패가 있던 항목은 수정 후 응답으로 다시 확인한다. 정답 요청·진행 요청·기록 권한과 충돌하는 새 관문이 없어야 한다.

### Task 3: I03 로드맵의 선택 기준 연결

1. `상향·보완·이동·재방문`에서 핵심 도움 후 적용·반복 오류·이미 충분한 독립 근거에 따른 선택을 현재 문장에 통합한다. 기존 두 변형 기준은 잠정 상향의 참고로 유지하고 이동을 막는 필수 시험으로 강화하지 않는다.
2. `한 수업의 진행`에는 목표 하나 → 필요한 설명 → 전체 독립 작업 → 실제 코드 리뷰의 짧은 흐름과 학습 스킬 링크를 둔다. 상세 요청별 대응은 스킬 한 곳에서 관리한다.
3. `주간 운영과 점검`에는 혼합·재방문을 선택하는 관찰 단서를 연결한다. 복습·대회가 생기면 신규 분량이나 다른 활동을 대체한다.
4. 가까운 목표인 파랑 도달을 위해 현재 공백을 우선한다는 선택 이유를 명확히 한다. 13개 주제 목록과 선택 심화를 그대로 보존한다.
5. 기존 첫 4주 계획을 실제 수행 결과로 바꾸거나 새 개편 날짜로 다시 시작하지 않는다. 다음 네 회차의 운영 관찰은 별도의 강사 점검이며 주간 예산 안에서 진행한다.

**완료 기준:** 여섯 예산표·목표·기존 앵커가 보존된다. 자세한 도움 절차와 시간표가 여러 문서에 복제되지 않는다.

### Task 4: I04 STATE와 과거 제안의 정합성 반영

적용 시점에도 중단 요청이 유효하면 STATE 첫 부분에 학습 중단과 개편 상태를 적는다. 이후 사용자가 재개했다면 실제 최신 요청에 맞춘다. 개편 적용 자체를 학습 재개로 처리하지 않는다.

`다음 독립 행동`은 다음 의미로 조정한다. 아래는 재개 지침의 내용이며 지금 부여하는 과제가 아니다.

> 재개 시 최신 코드와 현재 요청을 확인한다. 최근 상태·초기화·간선 처리의 공백을 볼 수 있는 과제 하나를 고른다. ABC277E 자료 없는 재현 또는 관련 새 변형 중 하나를 선택할 수 있으며, 문제의 사전 노출과 제공할 정보에 맞춰 재현·일반 연습·혼합을 구분한다. 선택한 과제의 이유와 완료 기준을 짧게 제시한다.

현재 T06 성과, 네 부분의 교정, 교정 후 AC·독립 재현 미확인, 보류 SCC 변형, 세그먼트 트리 질문, 날짜가 있는 계정 근거는 보존한다. 구체적인 구현·경계 검토 기준은 재개 때 고른 과제 하나에 맞춘다.

`docs/LEARNING_REVIEW.md`의 `다음 한 회차`에는 해당 내용이 2026-10-23 점검 당시 제안임을 한 문장으로 표시하고 STATE를 연결한다. ABC277E 복기의 다음 행동 항목도 같은 방식으로 당시 재현 제안과 현재 선택을 구분한다. 당시 코드·도움·실행·판정은 고치지 않는다.

**완료 기준:** 현재 필수 과제를 정하는 위치는 STATE 하나다. 과거 제안을 현재의 강제 재구현 지시로 읽게 하는 충돌이 해소된다.

### Task 5: I05 참고 자료에 학습 연구 연결

설계의 연구 표에서 아래 네 연구의 링크·역할·한계를 짧게 옮긴다. 원문 주장과 CP 수업에 적용한 판단을 구분하고, 표본·효과 크기·최적 주기를 새로 추정하지 않는다.

| 연구 | 참고 자료에서 설명할 역할 | 함께 유지할 한계 |
| --- | --- | --- |
| Atkinson·Renkl·Merrill, 2003 | 예제에서 독립 풀이로 넘어갈 때 도움 축소와 원리 설명을 연결하는 참고 | CP 실험이 아니며 모든 먼 전이를 보장하지 않음. |
| Margulieux·Morrison·Decker, 2020 | 코드 덩어리의 기능적 목적을 드러내는 설명의 참고 | 입문 수업의 준실험이며 평균 시험 점수의 유의한 개선은 확인하지 않음. |
| Roediger·Karpicke, 2006 | 즉시 이해와 나중의 기억에서 구성하는 활동을 구분하는 참고 | 글 기억 연구이며 CP 실력 향상량으로 환산할 수 없음. |
| Rohrer·Taylor, 2007 | 배운 유형의 혼합과 시간을 나눈 연습을 배치하는 참고 | 수학 연구이며 개인의 고정 복습 간격을 정하지 않음. |

USACO Guide 연습 안내는 기존 항목을 재사용한다. 도입부의 “이번 구현”처럼 시점이 모호한 표현은 해당 과거 확인 범위와 새 연구 절을 구분하는 표현으로 정리한다. 계정·플랫폼·도구의 확인일을 일괄 갱신하지 않는다. 외부 링크가 접근 불가하면 확인된 서지와 출처를 보존하고 최신 재검증이라고 쓰지 않는다.

**완료 기준:** 운영 규칙의 출처를 찾을 수 있고, 매회 모든 논문을 다시 읽는 절차가 생기지 않는다.

### Task 6: I06 통합 검증

문서 검사와 강사의 응답 검토를 나눠 수행한다. 메타데이터·문자열 검사는 행동 준수나 학습 효과의 증거로 쓰지 않는다.

1. 변경된 전체 문장을 다시 읽고 설계의 의도·현재 사용자 요청·기존 위임과 대조한다.
2. 아래 메타데이터 검사와 상대 링크·앵커 검사를 수행한다.
3. 학습 스킬의 YAML `name`·`description`과 기록 스킬 링크를 확인한다. SKILL·ROADMAP·STATE·REFERENCES는 서로 다른 형식이므로 노트 frontmatter를 새로 강제하지 않는다.
4. C01–C09를 대조하고, 스킬 수정이 있었으면 변경 전후 행동 검증을 마친다. 실패하면 해당 문구를 좁게 수정하고 영향을 받는 상황만 재검토한다.
5. ABC277E 공개 복기 수정은 웹의 콘텐츠 입력을 바꾸므로 배포 하위 경로의 로컬 빌드를 확인한다. 새 링크·변경 문장의 생성 결과를 확인하고, 본문 검색 확인이 필요하면 빌드 미리보기를 사용한다.
6. 변경 전후 해시와 diff를 비교한다. 보호 대상은 동일해야 하고, 계획한 문서 밖의 변경은 자동으로 묶거나 되돌리지 않는다.

메타데이터 검사는 저장소 루트에서 다음 대상으로 실행한다.

```bash
uv run --frozen python scripts/validate_notes.py docs/TEACHING_DESIGN.md docs/TEACHING_IMPLEMENTATION_PLAN.md docs/LEARNING_REVIEW.md atcoder/abc277e.md
git diff --check
```

상대 링크 검사는 위 네 문서와 ROADMAP·STATE·REFERENCES·학습 스킬의 Markdown 링크를 기존 `markdown-it-py` 환경에서 추출해 수행한다. 로컬 파일의 존재, 저장소 안 경로, 제목 앵커, 기존 앵커의 유입 링크를 확인한다. 검사용 코드는 임시 실행으로 처리하며 새 학습 도구를 만들지 않는다.

웹은 `web/`에서 기존 설치를 사용하고, 의존성이 없거나 lock과 일치하지 않으면 먼저 `npm ci`를 수행한다.

```bash
SITE_BASE=/algorithm-solutions/ npm run build
```

배포 하위 경로의 브라우저 검사는 같은 환경변수로 `npm run test:e2e`를 실행한다. 코드·도구·배포 설정까지 범위를 넓히게 되는 경우에만 관련 Python·웹 검사를 추가한다. 문서 개편을 위해 일반 풀이 회귀 테스트나 새 브라우저 테스트를 작성하지 않는다.

**완료 기준:** 문서·응답·보존·영향받는 공개 노트 검증의 실제 결과와 미실행을 구분해 보고할 수 있다. 검사 실패가 있으면 운영 반영 완료라고 표시하지 않는다.
