# 구축 검증 기록

확인일: 2026-09-20. 이 문서는 환경·웹 구축의 결과이며 학습자의 문제 해결 기록이 아니다.
앞부분은 1차 환경 구축 당시의 결과이고, 2차 결과는 아래 별도 항목에 이어 기록한다.

## 준비된 환경

| 항목 | 확인한 상태 |
| --- | --- |
| 개발 환경 | uv 0.12.13, `.venv` CPython 3.12.14 |
| 풀이 실행 환경 | `.venv-pypy` Python 3.10.16 / PyPy 7.3.19 |
| 편집기 | Windows VS Code 1.138.0 + WSL remote |
| WSL 확장 | CPH 2026.9.1789578855, LeetCode 0.18.4, Python 확장 설치 확인 |
| LeetCode 실행기 | 사용자 영역 Node.js 22.23.2 설치, 존재하지 않던 `leetcode.nodePath` 수정 |
| 브라우저 | Edge에 Competitive Companion Customized 1.6.0의 설치 파일 확인; 활성화와 버튼 동작은 미확인 |

생성된 두 워크스페이스의 기본 실행기는 CPython이며 단일 테스트 템플릿을 사용한다.
PyPy·다중 테스트 선택은 [사용법](USAGE.md)을 따른다. 기기별 절대경로와 실행 환경은 Git에서 제외된다.
LeetCode의 로그인·온라인 테스트·제출은 이번에 실행하지 않았다.

## 저장소와 템플릿

- 기존 플랫폼 풀이·작업 파일 및 루트 `main.py`, `ex.in`을 포함한 104개 파일을
  작업 전 SHA-256과 대조했고 모두 동일했다. 기존 LeetCode 메타데이터도 보존됐다.
- 워크스페이스 생성기·기록 검사기 자동 테스트 21개가 통과했다. 경로에 공백이 있는 별도
  체크아웃, 재실행 시 파일 불변, 잘못된 인터프리터·템플릿, 원본 풀이·CPH 데이터 보존을 포함한다.
- CPython과 PyPy에서 단일·다중 테스트 템플릿을 각각 임시 구현으로 실행했다.
  네 조합 모두 기대 출력을 얻었으며 0과 음수 입력도 포함했다. 이 코드는 학습 풀이로 저장하지 않았다.
- `uv lock --check`, `git diff --check`가 통과했다. GitHub Actions 검사 설정을 추가했으며
  실제 원격 실행 결과는 아래 2차 배포 항목에 기록했다.
- 1차 구축 당시 실제 학습 노트는 작성하지 않았다. 기본 기록 검사의 `0 note(s)`는 정상이며
  온라인 AC·독립 해결·숙달을 의미하지 않는다.
- 별도 임시 체크아웃에서 세 기록 템플릿에 실제 형식의 메타데이터와 더미 코드 경로를
  채워 검사했고 3개 모두 통과했다. 안내 문서 10개의 로컬 링크도 확인했다.

## 실제 CPH 확장 호스트 검증

Windows VS Code의 WSL 확장 테스트 호스트에서 CPH를 실행했다. 기존 수신 서버와
사용자 창을 유지하기 위해 `/tmp`에 설치 번들을 복사해 포트 상수를 27121에서 27122로 바꾸고,
실제 테스트 실행 함수를 호출할 수 있도록 테스트용 export를 추가했다.
설치된 원본 번들은 수정하지 않았다.

Companion 형식의 HTTP 데이터로 종료된 [AtCoder practice_1](https://atcoder.jp/contests/practice/tasks/practice_1)과
[Codeforces 4A](https://codeforces.com/problemset/problem/4/A)를 가져왔다.
문제별 파일 이름, 템플릿의 제목·URL 치환, 커서 자리 표시자 제거, 소스 옆 `.cph` 생성을 확인했다.
브라우저의 문제 파싱과 `+` 클릭은 이 테스트에 포함되지 않는다.

생성기를 복사한 별도 체크아웃에서 만든 multi-root 워크스페이스를 실제 호스트로 열어
첫 플랫폼 폴더, 둘째 저장소 폴더, PyPy 실행기·템플릿 경로, 5초 제한이 적용됨을 확인했다.
AtCoder는 공식 예제와 추가 입력 `2 / 3 4 / custom → 9 custom`, Codeforces는 공식 `8 → YES`와
추가 경계값 `2 → NO`를 실제 실행해 각 2개 모두 통과했다. 여기서 `/`는 입력 줄바꿈을 뜻한다.

PyPy를 사용하는 실제 CPH 실행에서 다음 판정을 확인했다.

| 입력한 프로그램 | 확인한 결과 |
| --- | --- |
| 기대 출력을 내는 프로그램 | `pass=true`, 종료 코드 0 |
| 틀린 출력을 내는 프로그램 | `pass=false`, 종료 코드 0 |
| 예외를 발생시키는 프로그램 | `pass=false`, 종료 코드 1, 예상 오류 출력 |
| 제한 시간을 넘기는 프로그램 | `pass=false`, `SIGTERM`, `timeOut=true` |

이 결과는 계측한 확장 복사본의 실행 검증이며, 설치 번들 그대로의 브라우저 전체 흐름이나
온라인 저지 판정 검증은 아니다. 기기에서 얻은 결과는 Git에서 제외한 `.local/validation/`에 둔다.
검증이 끝난 뒤 테스트용 창과 27122 수신기는 종료됐고 기존 27121 서비스는 유지됐다.

문제 데이터를 import 완료 전에 연속 전송하면 CPH에서 `Illegal argument: TextEditor`가 발생했다.
첫 파일이 열리고 커서가 놓인 뒤 다음 문제를 가져오는 순서에서는 정상 동작했다.

## 첫 사용 때 남은 확인

1. 생성한 플랫폼 워크스페이스 하나를 열고 종료된 문제 페이지에서 Companion의 `+`를 누른다.
2. 템플릿과 샘플이 나타나면 직접 풀이를 작성하고 `Ctrl+Alt+B`로 샘플·추가 반례를 실행한다.
3. 브라우저에서 제출하고 실제 저지 결과를 확인한다. LeetCode도 확장 로그인 후 별도로 확인한다.

연결이 안 되면 [수동 테스트·포트 확인 방법](USAGE.md)을 사용한다.
2차 웹의 실행과 배포 방법은 [웹 사용법](WEB.md)을 따른다.

## 2차: 콘텐츠와 내장 스킬

- 기초 참고 노트 5개, 기존 코드 설명 3개가 메타데이터·코드 경로·문서 링크 검사를 통과했다.
  과거 제출 판정·풀이 날짜·도움 여부는 추정하지 않았으며 실제 대회 기록은 아직 없다.
- 개념 노트의 Python 예제 6개를 CPython 3.12.14와 PyPy의 Python 3.10.16에서 실행해
  12회 모두 통과했다. 선택한 원본 풀이도 같은 두 환경에서 예제·경계 입력을 확인했으며,
  문제별 입력과 기대값은 해당 노트에 기록했다.
- 워크스페이스 생성기 8개와 기록 검사기 18개, 총 26개 자동 테스트가 통과했다.
  공개 노트의 raw HTML, 저장소 밖 경로, 비공개·scratch 경로, symlink와 잘못된 코드 연결을 포함한다.
- 2차 시작 시점과 비교해 플랫폼 풀이·`ex.in` 등 103개 파일의 SHA-256이 동일했다.
  루트 `main.py`에는 작업 도중 추가 편집이 있었으며 현재 내용을 유지하고 커밋에서 제외했다.
- 스킬 4개의 `SKILL.md` 형식을 공식 skill-creator 검사기로 확인했다. UI 메타데이터에
  한국어 설명과 `$스킬명` 호출 예시를 넣었고 자연어 선택을 허용했다.
- 독립 에이전트가 서로 분리된 임시 저장소에서 네 자연어 요청을 실제 수행했다.
  기존 개념 노트 갱신, 새 사실 없는 반복 요청의 무변경, 과거 문제 판정의 미확인 상태 유지,
  대회 시간 배분 기록, 학습 종료 시 노트·STATE 무변경을 확인했다.
  주 스레드가 실제 산출물과 변경 파일의 해시를 별도로 대조했다.
  시험용 대회·학습 경험은 이 저장소의 실제 기록에 넣지 않았다.
- 안내 문서·스킬 15개의 로컬 링크와 `git diff --check`를 확인했다.

## 2차: 학습 웹

| 검사 | 결과 |
| --- | --- |
| Astro 검사 | 오류·경고·힌트 0개 |
| 웹 단위 테스트 | 3개 파일, 4개 테스트 통과 |

| Playwright | 데스크톱·모바일 Chromium 8개 검사 통과 |

브라우저 검사에서 검색과 URL 필터, 다크 모드 유지, 모바일 메뉴, 수식·코드,
문서 연결, JavaScript 없는 본문 읽기, 빈 대회 목록과 점을 포함한 문제 주소를 확인했다.
문제 페이지에 표시한 Python 텍스트는 원본 전체와 대조했다. 긴 원본 코드는 검색 색인에서 제외한다.
한글 폰트를 적용한 데스크톱·모바일 스크린샷도 확인했다.
생성된 HTML 15개의 내부 링크·목차 앵커·정적 자원 참조 641개를 검사해 누락이 없음을 확인했다.

Astro의 빈 `contests` 컬렉션 안내는 현재 기록이 없는 상태를 알리는 메시지이며 빌드 실패가 아니다.
로컬 브라우저 검사는 임시 디렉터리에 준비한 시스템 라이브러리·폰트를 사용했고,
GitHub Actions는 `playwright install --with-deps chromium`과 한글 폰트 설치로 환경을 준비한다.

## 공개 배포 확인

GitHub Pages를 Actions 방식으로 활성화하고 1·2차 변경을 `main`에 커밋·push했다.
첫 구축 커밋 `2c730a6`의 [Actions 실행](https://github.com/10o0o/algorithm-solutions/actions/runs/35486222483)에서
`check`, `frontend`, `deploy`가 모두 성공했다.

2026-09-20에 [공개 사이트](https://10o0o.github.io/algorithm-solutions/)를 실제 Chromium으로 열어 확인했다.

- 홈 HTTP 200, 한국어 `누적` 검색과 `BFS` 검색·유형·분야·태그의 복합 필터, 플랫폼 필터가 동작했다.
  검색어와 필터가 새로고침 뒤에도 URL에 유지됐다.
- 점이 포함된 1422 문제 주소에서 Python 원문 일치, 수식, 관련 개념 링크와 다크 모드 유지를 확인했다.
  원본 코드에만 있는 `cnts`는 검색 결과에 나오지 않았다.
- 빈 대회 목록, 모바일 메뉴·가로 폭, JavaScript를 끈 본문 읽기를 확인했다.
  검사 중 공개 사이트의 실패한 자원 요청과 JavaScript 실행 오류는 없었다.

이 결과는 웹 배포 검증이며 위의 Companion 브라우저 버튼·온라인 저지 제출 미확인 상태를 바꾸지 않는다.

  기존 풀이·학습 노트·STATE·템플릿은 변경하지 않았으며 CSES 정답 코드를 새로 만들지 않았다.

  템플릿 치환과 메타데이터 저장 방식을 대조했다. 링크는 [CSES 안내](../cses/README.md#지원-근거)에 있다.
  사용자 PC의 확장 설치·브라우저 버튼·수신 연결·온라인 제출은 이번에 실행하지 않았다.
