# 알고리즘 학습 이어가기

## 재개 위치와 과제 선택

[현재 위치](../../../STATE.md)에서 다음 행동과 확인된 범위를 읽고, [로드맵](../../../ROADMAP.md)의 주제 순서를 따른다. 필요한 경우 [참고 자료](../../../docs/REFERENCES.md), 해당 문제·자료, 실제 사용자 코드와 실행 결과를 확인한다. 필요한 문제·진단은 관련 코드·결과·풀이 이력과 중복 여부를 확인해 에이전트가 고른다.
STATE와 현재 코드·대화가 다르면 확인한 차이를 설명하고 현재 재개 범위를 맞춘다. 이것만으로 STATE를 자동 갱신하지 않는다.

- 사용자가 지정한 주제가 있으면 그 범위를 우선한다. 이미 구현하거나 설명한 기초 문법을 처음부터 다시 묻지 않는다.
- 시작 수준은 실제 풀이·코드·결과로 조정한다. 필요하면 기존 코드·결과를 바탕으로 한 대표 진단 하나로 현재 위치를 잠정 판단할 수 있지만, 한 번의 성공이나 파일 존재·샘플 통과를 숙달로 기록하지 않는다.
- 과거 코드의 도움 여부·제출 판정이 불명확하면 미확인으로 두고 현재 이해·구현을 확인할 과제로 진행한다. 과거 이력 답변을 수업 시작이나 기초 생략의 필수 조건으로 만들지 않는다.
- Codeforces 기준선은 학습 재개의 선행 조건이 아니다. 대회와 측정용 virtual은 로드맵의 주기적 점검으로 활용한다.

## 한 회차의 학습

먼저 오늘의 구체적인 목표, 지금 다룰 이유, 완료 기준을 짧게 밝힌다. 기본 과제는 학습자가 설계하고 구현해 실행한 뒤 설명·검토하는 하나의 충분한 작업으로 잡는다.

- 새 기법을 배우는 회차에는 핵심 생각과 필요한 예시를 먼저 설명한다. 아직 배우지 않은 알고리즘을 먼저 알아내야만 수업을 시작할 수 있게 하지 않는다. 기법을 익히는 과제에서는 다룰 기법을 밝혀도 된다.
- 이미 배운 주제의 재현과 혼합 연습은 먼저 독립 시도하게 한다. 주제별 재현 과제에서는 대상 기법을 알려도 된다. 접근 선택을 점검하는 혼합 과제에서는 시도 전에 문제 태그·분류·접근 방향을 드러내지 않는다.
- 연속된 한 줄 확인 질문을 기본 흐름으로 삼지 않는다. 관찰된 특정 오개념·구현 공백이 있거나 사용자가 요청하면 그 부분만 작게 나누고, 해결되면 다시 전체 과제로 돌아간다. 힌트도 다음 독립 행동을 돕는 범위로 제한한다.
- 풀이 코드는 사용자가 요청할 때 제공하고, 도움받은 범위를 구분한다. 학습자는 직접 설계·구현·실행한다. 리뷰는 실제 코드와 관찰한 출력에 근거하며, 좁은 검증이 필요하면 해당 문제의 샘플·필요한 반례만 격리해 실행한다. 사용자 코드 수정은 요청한 범위로 한정한다.
- 필요하면 공식 문제의 제약, 사용할 Python 버전과 저지 환경을 확인한다. 문제 파일, 설정, 샘플 통과만으로 독립 해결이나 AC를 추정하지 않는다.

실전 대회 중에는 풀이·디버깅 도움을 주지 않고 종료 뒤 리뷰한다. 측정용 virtual은 제한 시간이 끝날 때까지 접근 힌트 없이 진행한다. 사용자가 수업 방식 점검 등을 위해 학습을 멈추면 새 연습 질문을 이어서 내지 않는다.

## 증거와 기록

다음 사실을 섞지 않는다. 확인되지 않은 항목은 미확인으로 남긴다.
다른 세션의 질문·관심 주제는 배경이며 이 저장소에서 학습·해결을 마친 증거가 아니다.

- 작성·도움: 사용자 작성, 힌트 후 작성, AI 제공, AI 수정. 파일만 보고 작성 주체를 추정하지 않는다.
- 실행: 실행한 사람·환경·코드 버전 또는 파일·입력 범위·실제 결과. 예상값과 실행값을 구분한다.
- 온라인 판정: 공식 내역 직접 확인과 사용자 보고 AC/WA/TLE를 구분한다. 샘플·회귀 통과는 AC가 아니다.
- 재현: 같은 세션 추가 도움 없는 재구현, 다른 날 자료 없는 재구현, 새 문제 독립 적용을 구분한다.

기록할 때 코드 → 테스트 명령/반례 → 해당 문제·개념 노트가 이어지게 실제 상대 링크를 쓴다.
일반 문제에는 필요한 반례만 남기고, 반복 활용하는 구현·도구에만 작은 회귀 테스트를 둔다.
파일마다 새 진도표나 세션별 복제 노트를 만들지 않는다. 일반 설명·힌트·`이해했어`만으로
학습 경험을 자동 생성하지 않는다.


## 피드백과 기록

현재 접근과 막힌 지점을 코드·설명·결과에서 확인하고, 이미 제출한 내용을 다시 처음부터 요구하지 않는다. 한 번의 세션에서 보인 진전, 잠정적인 주제 배치, 이후 독립 재현이나 새 문제 적용으로 확인할 숙달을 구분한다.

일반 설명, 힌트, `이해했어`만으로 노트·진도·사용자 코드를 갱신하지 않는다. `오늘 학습 종료`에는 진행을 멈추고 남은 질문과 다음 독립 행동을 짧게 제안하며 파일을 쓰지 않는다. `STATE 반영해` 또는 동등한 명시 요청이 있으면 실제 확인한 현재 범위와 다음 행동만 STATE에 저장한다. 사용자가 교육과정 개편을 명시적으로 승인한 경우에는 승인된 범위의 ROADMAP·STATE·요청된 스킬을 함께 반영할 수 있다.

`개념 정리해줘`, `문제 복기해줘`, `이번 대회 복기해줘`는 각각 [지식 정리](../record-algorithm-knowledge/SKILL.md), [문제 복기](../review-algorithm-problem/SKILL.md), [대회 복기](../review-algorithm-contest/SKILL.md)로 연결한다. `정리해줘`만 있으면 대상이 명확할 때 그 범위만 저장하고, 불명확할 때만 묻는다.

샘플 통과나 설명을 들었다는 사실을 온라인 AC·독립 해결·숙달로 바꾸지 않는다. 이 학습 스킬은 커밋·push·배포를 자동 수행하지 않는다.

노트·STATE 갱신은 현재 요청 또는 현재 대화에서 확인된 위임 범위에서만 수행한다. 기존 노트의 위임 언급만으로 새로운 권한을 만들지 않으며, 이미 확인된 승인을 다시 요구하지 않는다.

커밋·push가 명시적으로 요청되면 [저장소 동기화 규칙](../../../AGENTS.md#저장과-원격-동기화)에 따라 검증하고 원격 SHA·CI·Pages 상태를 확인한다. 학습 종료 보고에서는 확인된 결과·미확인 범위·다음 행동과 로컬 저장·원격 반영 상태를 구분한다.
