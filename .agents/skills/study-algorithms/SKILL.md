# 알고리즘 학습 이어가기

## 시작: 현재 증거와 한 목표

[저장소 지침](../../../AGENTS.md) → [현재 위치](../../../STATE.md) → 그 안에서 연결한
코드·노트의 최신 부분 순으로 읽는다. [로드맵](../../../ROADMAP.md)은 주제 선택이나 운영을
조정할 때 참고한다. 목록은 우선순위이며 이미 아는 기초의 강제 재수강 순서가 아니다.

현재 사용자 요청을 우선한다. STATE와 파일·대화가 다르면 새로 확인한 사실을 먼저 짚고
재개 위치를 맞춘다. 파일 존재를 독립 구현으로 추정하지도, 오래된 문장을 근거로 구현을
안 했다고 단정하지도 않는다. 사용자 코드나 충분한 설명이 이미 있으면 다시 요구하지 않는다.

이번 목표 하나, 현재 막힌 질문 하나, 바로 할 행동 하나만 정한다. 시작 확인 질문을
의식처럼 반복하거나 매번 퀴즈·시간 측정·숙제를 강제하지 않는다. 질문이 꼭 필요하면
없는 정보 중 다음 선택을 바꾸는 것만 묻는다. 막힌 질문이 아직 관찰되지 않았다면 그렇게 적는다.

## 진행: 힌트와 사용자 시도

- 기본은 작은 힌트 하나 → 사용자 시도 → 실제 코드·출력에 근거한 피드백이다.
  한 번에 전체 풀이를 쏟거나 사용자가 시도하기 전에 다음 힌트를 연달아 주지 않는다.
- 설명·구체적인 예·모범풀이를 요청하면 제공한다. 정답을 원한다는 요청을 불필요한
  소크라테스식 질문으로 막지 않으며, 제공한 코드와 도움 범위를 구분한다.
- 풀이 코드 수정은 요청한 범위에서만 한다. 사용자가 직접 고칠 기회를 기본으로 두며,
  에이전트가 수정한 부분을 사용자 독립 작성으로 기록하지 않는다. 원본 시도는 diff나
  짧은 실패 기록으로 보존하고 미확인 사용자 파일·CPH 반례를 덮어쓰지 않는다.
- 오류를 발견하면 가장 작은 재현 입력·기대값·실제값으로 짚는다. 필요한 테스트는 격리 실행한다.
  테스트 작성과 실행을 에이전트가 했다면 그 주체를 기록한다.
- 진행 중 실전 대회와 기준선 측정용 virtual은 제한 시간이 끝난 뒤 풀이·디버깅을 돕는다.

## 증거와 기록

다음 사실을 섞지 않는다. 확인되지 않은 항목은 미확인으로 남긴다.
다른 세션의 질문·관심 주제는 배경이며 이 저장소에서 학습·해결을 마친 증거가 아니다.

- 작성·도움: 사용자 작성, 힌트 후 작성, AI 제공, AI 수정. 파일만 보고 작성 주체를 추정하지 않는다.
- 실행: 실행한 사람·환경·코드 버전 또는 파일·입력 범위·실제 결과. 예상값과 실행값을 구분한다.
- 온라인 판정: 공식 내역 직접 확인과 사용자 보고 AC/WA/TLE를 구분한다. 샘플·회귀 통과는 AC가 아니다.
- 재현: 같은 세션 추가 도움 없는 재구현, 다른 날 자료 없는 재구현, 새 문제 독립 적용을 구분한다.

기록할 때 코드 → 테스트 명령/반례 → 해당 문제·개념 노트가 이어지게 실제 상대 링크를 쓴다.
일반 문제에는 필요한 반례만 남기고, 반복 활용하는 구현·도구에만 작은 회귀 테스트를 둔다.
파일마다 새 진도표나 세션별 복제 노트를 만들지 않는다. 일반 설명·힌트·`이해했어`만으로
학습 경험을 자동 생성하지 않는다.

`개념 정리해줘`, `문제 복기해줘`, `이번 대회 복기해줘`는 각각
[지식 정리](../record-algorithm-knowledge/SKILL.md),
[문제 복기](../review-algorithm-problem/SKILL.md),
[대회 복기](../review-algorithm-contest/SKILL.md)로 연결한다.
요청 또는 현재 대화에서 확인된 위임 범위에서만 노트·STATE를 갱신한다. 기존 노트의
위임 언급만으로 새로운 권한을 만들어 내지 않으며, 이미 확인된 승인을 다시 요구하지 않는다.

## 종료와 다음 세션

`오늘 학습 종료`에는 추가 수업을 멈추고 다음을 짧게 정리한다.

1. 이번에 확인한 것과 아직 미확인인 것. 코드·실행·사용자 보고를 구별한다.
2. 미해결 질문과 다음 한 행동. 필요한 복습은 하나만 제안하고 시점은 합의된 경우에만 적는다.
3. 저장 상태. STATE 저장이 요청되거나 위임된 경우 목표·근거 링크·남은 질문·다음 행동만 갱신한다.
   권한이 없으면 저장할 체크포인트를 제안한다. 전체 역사는 기존 노트에 보존한다.
4. 원격 상태. 커밋·push가 승인됐으면 [저장소 동기화 규칙](../../../AGENTS.md#저장과-원격-동기화)에
   따라 검증하고 원격 SHA까지 확인한다. 승인되지 않았다면 로컬 저장까지만인지 정확히 보고한다.

STATE는 전체 수업 대본이 아니다. 이미 확인한 구현을 첫 입문으로 되돌리지 않고,
지연 재현·독립 적용 등 실제 남은 불확실성부터 다음 세션을 시작한다.
