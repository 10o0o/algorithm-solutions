# 알고리즘 학습 이어가기

## 재개 위치와 과제 선택

[현재 위치](../../../STATE.md)에서 다음 행동과 확인된 범위를 읽고, [로드맵](../../../ROADMAP.md)의 주제 순서를 따른다. 필요한 경우 [참고 자료](../../../docs/REFERENCES.md), 해당 문제·자료, 실제 사용자 코드와 실행 결과를 확인한다. 현재 공백 또는 목표에 연결되는 과제 하나를 관련 코드·결과·풀이 이력과 중복 여부에 맞춰 고르고, 선택 이유를 짧게 제시한다.
STATE와 현재 코드·대화가 다르면 확인한 차이를 설명하고 현재 재개 범위를 맞춘다. 이것만으로 STATE를 자동 갱신하지 않는다. 공유 노트의 코드 링크는 추적되는 플랫폼 풀이를 사용한다. Git에서 제외된 scratch가 없으면 공유 코드와 확인된 남은 범위에서 이어가고, 계정 재조회가 안 되면 마지막 확인일·출처·한계를 밝힌다.

- 사용자가 지정한 주제가 있으면 그 범위를 우선한다. 이미 구현하거나 설명한 기초 문법을 처음부터 다시 묻지 않는다.
- 시작 수준은 실제 풀이·코드·결과로 조정한다. 필요하면 기존 코드·결과를 바탕으로 한 대표 진단 하나로 현재 위치를 잠정 판단할 수 있지만, 한 번의 성공이나 파일 존재·샘플 통과를 숙달로 기록하지 않는다.
- 과거 코드의 도움 여부·제출 판정이 불명확하면 미확인으로 두고 현재 이해·구현을 확인할 과제로 진행한다. 과거 이력 답변을 수업 시작이나 기초 생략의 필수 조건으로 만들지 않는다.
- Codeforces 기준선은 학습 재개의 선행 조건이 아니다. 대회와 측정용 virtual은 로드맵의 주기적 점검으로 활용한다.
- 접근 선택을 점검할 후보는 사전 노출을 확인한다. 이미 문제·해설을 봤으면 기출 재풀이/일반 연습 또는 다른 후보로 돌리고, 노출 미확인을 미견 측정의 성공 근거로 쓰지 않는다. 확인된 A–E 기록 다음에는 적정 새 문제나 F/G 후보에서 접근 선택·정당성·구현·시간 배분 중 실제 막힌 단계를 관찰한다. 문제 문자만으로 난도·약점·미시도를 단정하지 않는다.

## 한 회차의 학습

먼저 오늘의 구체적인 목표 하나, 지금 다룰 이유, 완료 기준을 짧게 밝힌다. 새 기법 학습·주제별 재현·혼합 연습·대회/측정 중 이번 방식을 정하고, 기본 과제는 학습자가 설계하고 구현해 실행한 뒤 설명·검토하는 하나의 충분한 작업으로 잡는다. 난도 상향·선수 보완·이동·재방문과 주간 시간은 [로드맵의 전환 기준](../../../ROADMAP.md#상향보완이동재방문)과 [예산](../../../ROADMAP.md#여섯-주간-예산)을 따른다. 수치 표를 이 스킬에 복제하지 않는다.

| 수업 방식 | 처음 제공할 것과 독립 작업 |
| --- | --- |
| 새 기법 | 목적·원리·확인한 작은 예제·적용 조건을 설명한 뒤 전체 설계·구현·실행을 맡긴다. 기법을 알려도 되며 처음부터 독립 발견을 요구하지 않는다. |
| 혼합 연습 | 원문과 실행 준비를 제공하고 접근 선택부터 시도하게 한다. 강사가 추가하는 태그·추천 기법·함수명·주석으로 해법을 먼저 드러내지 않는다. |
| 다른 날 재현 | 대상 기법을 알릴 수 있다. 자료 없는 재풀이 또는 새 변형 적용 중 필요한 과제 하나를 고르고, 사전 노출·추가 도움을 구분한다. |

연속된 한 줄 확인 질문을 기본 흐름으로 삼지 않는다. 관찰된 공백이나 요청에 맞춰 필요한 부분만 나눈 뒤 전체 구현·실행으로 돌아간다. 이미 보여준 설명·코드·결과를 같은 사전 퀴즈로 다시 요구하지 않는다.

| 관찰한 막힘 | 먼저 제공할 도움 |
| --- | --- |
| 문제의 목적·허용 행동이 불분명함 | 입력 하나의 실제 행동과 목표를 보여주고 현재 변수·코드와 연결한다. |
| 새 기법을 모름 | 필요한 원리·작은 예제·조건을 먼저 가르친다. 선수 전체를 새 과정으로 늘리지 않는다. |
| 선택의 근거가 불분명함 | 작은 상태·선택을 비교한다. 잘못된 접근은 반례로, 타당한 접근은 필요한 논증으로 설명한다. |
| 상태 의미와 코드가 다름 | 한 번의 실제 전이를 추적해 해당 줄과 대응시킨다. 관련 오류는 한 번의 리뷰에 묶는다. |
| 문법·입출력·단순 인덱스만 막힘 | 필요한 설명이나 위임된 작은 수정 후 원래 과제로 돌아간다. |
| 적용 조건·복잡도가 불확실함 | 현재 풀이와 실제 제약에 필요한 범위만 확인한다. |

같은 설명 뒤에도 이해가 어렵다면 시간표·DP 표·상태 이동처럼 표현을 바꾼다. 힌트·핵심 설명·부분 코드 중 실제 막힘에 필요한 도움을 고른다. 모든 도움 단계를 거치게 하거나 고정 시간이 지나면 해설을 자동 공개하지 않는다. 새 아이디어를 탐색 중이면 독립 작업을 이어간다.

**코드 리뷰 순서:** 저장된 최신 파일 → 접근의 타당성 → 작은 입력의 기대값·현재 실행/추적 → 첫 잘못된 판단·전이와 관련 수정 → 필요한 샘플·반례 검증. 참고 풀이와 다르게 표현한 타당한 접근을 보존한다. 작은 반례와 코드가 실행 가능한 형태로 있으면 격리 실행해 관찰한 정렬 순서·상태 변화·출력에 근거해 설명한다. 실행이 불가능하면 미실행 추적임을 밝히고 실제 입력과 전후 값을 대응시킨다. 설명용 예제의 가능한 배정·기대값과 끝점 포함 조건도 확인한다. 이 검증은 강사가 맡으며 실행하지 않은 값을 실행 결과라고 쓰지 않는다.

수정은 확인된 요청·위임 범위 안에서 한다. 사소한 수정 대행을 맡겼으면 처리·검증하고 같은 승인을 다시 묻지 않는다. 한 줄이라도 핵심 상태·불변식에 해당하면 의미와 반례를 함께 설명하며, 직접 수정했는지 도움받았는지 구분한다. 사용자가 함께 편집 중이면 적용 직전 해당 내용을 다시 읽고 달라진 버전으로 재검토한다.

| 사용자 요청 | 다음 행동 |
| --- | --- |
| `완료`, AC 보고 | 최신 코드와 필요한 실행을 확인해 피드백한다. 사용자 보고 AC와 직접 확인·로컬 통과를 구분한다. |
| `모범 코드`, 정답 요청 | 요청한 코드를 제공하고 전체 흐름·도움 범위를 설명한다. 강제 재시험을 붙이지 않는다. |
| `다음` | 확인한 성과를 인정하고 다음 과제 하나를 고른다. 미확인은 짧게 구분하고 모든 AC 문제의 재구현을 관문으로 삼지 않는다. |
| `입력 같은 것만 세팅` | 입력·빈 시그니처·출력 연결 중 요청한 준비만 한다. 알고리즘 본문은 학습자에게 남긴다. |
| 가독성 검토 | 정확성과 읽기 쉬운 흐름에 필요한 소수 변경을 검토한다. |

CPH·입력 도구 문제는 강사가 처리하고, 길어지면 일반 실행과 샘플 입력으로 복귀한다. 도구 진단을 학습자 과제로 배정하거나 기록·배포·저장소 운영을 풀이 과제에 추가하지 않는다. 필요하면 공식 제약과 선택한 Python·저지 환경을 확인한다. 일반 풀이 검증은 샘플·원인을 가르는 반례를 우선하고 미해결 우려가 있을 때만 넓힌다.

실전·측정용 virtual 중에는 AI 풀이·디버깅 도움을 주지 않고 제한 시간이 끝난 뒤 복기한다. 도움을 받은 virtual은 일반 연습으로 구분하며, 도움·노출이 미확인이면 독립 측정 확정은 보류한다. 사용자가 수업 방식 점검 등을 위해 학습을 멈추면 새 연습 질문을 이어서 내지 않는다.

## 증거와 기록

다음 사실을 섞지 않는다. 확인되지 않은 항목은 미확인으로 남긴다.
다른 세션의 질문·관심 주제는 배경이며 이 저장소에서 학습·해결을 마친 증거가 아니다.

- 날짜·대상: 관찰일, 상대 코드 경로·확인 가능한 버전, 실제 문제/노트 링크. 기기 절대경로·사생활을 넣지 않는다.
- 작성·도움: 사용자 작성, 힌트 후 작성, AI 제공/수정, 미확인과 도움의 시점·영향받은 부분. 파일만 보고 작성 주체를 추정하지 않는다.
- 설명: 적용 조건·정당성·상태/불변식·복잡도 중 실제 확인한 범위. 설명을 들은 것과 학습자가 설명한 것을 구분한다.
- 실행: 사용자/에이전트/미확인의 실행 주체, 필요한 Python·저지 환경, 실제 코드·샘플/반례·예상값·실제 출력과 통과/불일치/미실행. 예상값을 실행 결과로 쓰지 않는다.
- 온라인 판정: 확인한 AC/WA/TLE 또는 미확인과 공식 내역 직접 확인·사용자 보고·비공식 제출 자료의 출처. 샘플·회귀 통과는 AC가 아니다.
- 시간: 관찰/사용자 보고·근사 여부 또는 미측정. 대회 시작부터의 누적 AC 시각은 문제별 순수 사고·구현 시간이 아니다.
- 재현: 같은 세션/날짜의 추가 도움·자료 사용 여부와 실제 재구현 결과, 별도 날짜의 자료·핵심 도움 없는 직접 구현과 검증 결과, 다른 문제의 노출·접근 선택·정당성·직접 구현과 도움을 각각 구분한다.

기록 요청이 있을 때 노트 유형에 맞는 사실을 기존 본문에 필요한 만큼 남긴다. 새 필수 메타데이터나 진도 상태를 만들지 않는다. 모든 과거 항목의 답변을 학습 진입 조건으로 요구하지 않으며, 예정·파일 존재·샘플·에이전트 검증만으로 사용자 수행·독립 해결·숙달로 승격하지 않는다.

기록할 때 코드 → 테스트 명령/반례 → 해당 문제·개념 노트가 이어지게 실제 상대 링크를 쓴다.
일반 문제에는 필요한 반례만 남기고, 반복 활용하는 구현·도구에만 작은 회귀 테스트를 둔다.
파일마다 새 진도표나 세션별 복제 노트를 만들지 않는다. 일반 설명·힌트·`이해했어`만으로
학습 경험을 자동 생성하지 않는다.


## 종료와 다음 세션

현재 접근과 막힌 지점을 코드·설명·결과에서 확인하고, 이미 제출한 내용을 다시 처음부터 요구하지 않는다. 한 번의 세션에서 보인 진전, 잠정적인 주제 배치, 이후 독립 재현이나 새 문제 적용으로 확인할 숙달을 구분한다.

일반 설명, 힌트, `이해했어`만으로 노트·진도·사용자 코드를 갱신하지 않는다. `오늘 학습 종료`에는 진행을 멈추고 남은 질문과 다음 독립 행동을 짧게 제안하며 파일을 쓰지 않는다. `STATE 반영해` 또는 동등한 명시 요청이 있으면 실제 확인한 현재 범위와 다음 행동만 STATE에 저장한다. 사용자가 교육과정 개편을 명시적으로 승인한 경우에는 승인된 범위의 ROADMAP·STATE·요청된 스킬을 함께 반영할 수 있다.

`개념 정리해줘`, `문제 복기해줘`, `이번 대회 복기해줘`는 각각 [지식 정리](../record-algorithm-knowledge/SKILL.md), [문제 복기](../review-algorithm-problem/SKILL.md), [대회 복기](../review-algorithm-contest/SKILL.md)로 연결한다. `정리해줘`만 있으면 대상이 명확할 때 그 범위만 저장하고, 불명확할 때만 묻는다.

샘플 통과나 설명을 들었다는 사실을 온라인 AC·독립 해결·숙달로 바꾸지 않는다. 이 학습 스킬은 커밋·push·배포를 자동 수행하지 않는다.

노트·STATE 갱신은 현재 요청 또는 현재 대화에서 확인된 위임 범위에서만 수행한다. 기존 노트의 위임 언급만으로 새로운 권한을 만들지 않으며, 이미 확인된 승인을 다시 요구하지 않는다.

커밋·push가 명시적으로 요청되면 [저장소 동기화 규칙](../../../AGENTS.md#저장과-원격-동기화)에 따라 검증하고 원격 SHA·CI·Pages 상태를 확인한다. 학습 종료 보고에서는 확인된 결과·미확인 범위·다음 행동과 로컬 저장·원격 반영 상태를 구분한다.
