# 재사용할 알고리즘 지식 정리

[작성 규칙](../../../knowledge/README.md)과 [기존 템플릿](../../../knowledge/template.md)을 읽고,
요청 주제와 관련된 기존 노트·풀이·현재 대화만 확인한다. 같은 개념의 기존 노트를 우선 갱신한다.
과거 세션이나 Git 이력에서 학습 경험을 복원하지 않는다.

## 내용과 범위

정리 요청은 해당 노트 작성을 허용한다. 완성 가능한 내용에 대해 초안 승인이나
독립 설명 시험을 추가로 요구하지 않는다. 사용자가 이미 아는 기초의 참고 정리를 요청하면
정의·조건·불변식·작은 예·복잡도·Python 주의점을 작성한다.
사용자의 실제 경험은 대화·코드·확인한 결과에 근거한 범위만 포함한다.

새로 설명한 일반 지식과 사용자가 직접 시도했다고 확인한 사실을 혼동하지 않는다.
이해·독립 해결·제출 결과를 추정하지 않으며, 출처는 자신의 설명으로 정리하고 원문을 연결한다.
새 노트는 `knowledge/<분야>/<개념>.md`, 날짜는 실제 수정일, 제목은 H1과 일치시킨다.
Markdown·수식·코드 블록을 사용하고 raw HTML이나 템플릿 안내 주석은 남기지 않는다.

확인된 적용 사례가 있으면 실제 문제 노트 또는 코드에 상대 링크를 건다.
웹이 관계를 추출하므로 별도 연결 목록 데이터베이스를 만들지 않는다.
기존의 유효한 내용과 링크는 보존하고, 중복 주제·날짜별 복제 노트를 만들지 않는다.
변경할 새 내용이 없으면 그대로 두고 이유를 설명한다.

## 검증과 보고

저장소 루트에서 변경한 노트 경로를 지정해 검사한다.

```bash
uv run --frozen python scripts/validate_notes.py knowledge/<분야>/<개념>.md
git diff --check
```

새 Python 예제는 필요한 작은 입력과 경계 조건으로 검증한다. 검증은 예제의 동작을
확인하는 것이며 학습자의 숙달 판정이 아니다. 변경한 경로와 확인 결과를 보고한다.
이 노트 요청만으로 풀이 코드 수정·STATE 갱신·커밋·push·배포 권한을 확대하지 않는다.
현재 요청 또는 현재 대화에서 확인된 기존 위임이 그 범위를 포함하면
[학습 스킬](../study-algorithms/SKILL.md#종료와-다음-세션)과
[원격 동기화 규칙](../../../AGENTS.md#저장과-원격-동기화)을 따른다.
