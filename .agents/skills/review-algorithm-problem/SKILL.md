# 문제 풀이 복기

요청한 문제의 기존 코드, 같은 이름의 `.md`, 현재 대화와 실제 테스트·제출 결과를 읽는다.
실전 대회가 진행 중이면 종료 후 복기로 돌린다. 어떤 문제인지 결정할 수 없을 때만
대상을 묻고, 이미 명시된 문제에 대해 기록 승인을 반복하지 않는다.

[문제 템플릿](../../../templates/problem-note.md)을 재사용하되 해당 문제에 필요한 항목만 쓴다.
코드 옆 동일한 basename의 `.md`에 `title`, `updated`, `tags`, `url`, `solution`을 둔다.
`url`은 확인한 원문 HTTPS 주소, `solution`은 노트 기준 플랫폼 폴더 안의 `.py` 상대경로다.

## 기록할 내용

- 실제 코드의 핵심 관찰·접근, 정당성, 시간·공간 복잡도를 설명한다.
- 막힌 지점·실패 이유·사용한 힌트·재풀이 경험은 확인된 경우만 적는다.
- 필요한 반례는 입력과 기대 출력을 함께 남긴다. 테스트했다면 어떤 실행 환경에서
  어떤 범위를 확인했는지 적고, 로컬 샘플 통과와 온라인 판정을 구분한다.
- 과거 결과를 모르면 미확인으로 남긴다. 코드가 있거나 현재 테스트가 통과해도
  과거 AC·독립 구현·무힌트 해결로 기록하지 않는다.
- 관련 개념·대회 문서가 실제로 있을 때 상대 링크를 추가한다. 없는 노트를 미리 링크하지 않는다.

사용자가 기존 코드의 설명을 파일로 남겨 달라고 요청한 경우에도 이 형식을 사용한다. 작성 과정에서 발견한
코드 문제는 설명에 남기고, 별도 수정 요청 없이 원본 코드를 개선본으로 덮어쓰지 않는다.
CPH 테스트나 scratch 파일을 이동·초기화하지 않는다. raw HTML과 템플릿 안내 문구를 제거한다.
같은 요청이 반복되면 기존 복기에 새로 확인한 내용만 병합한다.

## 검증과 보고

저장소 루트에서 변경한 문서만 검사한다.

```bash
uv run --frozen python scripts/validate_notes.py <문제-노트.md>
git diff --check
```

검증이 필요한 코드는 샘플·핵심 반례만 격리 실행한다. 일반 풀이마다 상시 테스트 모음을
추가하지 않는다. 문서 경로, 확인한 결과와 남은 불확실성을 보고한다.
이 기록 요청만으로 STATE 변경·커밋·push·배포 권한을 확대하지 않는다. 현재 요청 또는
현재 대화에서 확인된 기존 위임이 있으면 [학습 스킬](../study-algorithms/SKILL.md#종료와-다음-세션)과
[원격 동기화 규칙](../../../AGENTS.md#저장과-원격-동기화)을 따른다.
